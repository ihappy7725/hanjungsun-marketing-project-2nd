# HOME 탭 사용 설명

> 담당: 정주연 · 2026-10-26 기준
> 이 문서는 **쓰는 법**만 담습니다. 왜 그렇게 만들었는지와 개발 내용은 [README.md](README.md)에 있습니다.

## 이 탭이 하는 일, 한 줄

**베트남 현지 일정에 맞춰 캠페인을 역산해주고, 오늘 무엇을 해야 하는지 알려주는 탭.**

달력은 수단입니다. 이 탭의 핵심은 **"목표일을 정하면 준비 업무가 날짜까지 자동으로 깔리는 것"**입니다.

---

## 1. 화면 구성

| 위치 | 이름 | 하는 일 |
|---|---|---|
| 맨 위 | 시계 | 한국·베트남 현재 시각. 업무 기준은 **한국 시간** |
| 왼쪽 큰 상자 | 캘린더 / 이벤트 기획 | 두 화면이 한자리에서 버튼으로 바뀜 |
| 왼쪽 아래 | 현지 뉴스 | 직접 검색 + 검증된 규제·공지 |
| 오른쪽 위 한 상자의 위쪽 | 이벤트 업무 진척 | 선택한 이벤트의 완료율 |
| 같은 상자의 구분선 아래 | 오늘의 해야 할 일 | 그날 마감인 업무, 지난 미완료 업무 |
| 오른쪽 | 현지 기회 | 앞으로 다가오는 베트남 일정 |
| 오른쪽 | 인플루언서 협업 요약 | 다른 탭에서 가져온 협업 현황 |

**오른쪽 위 선택 세 개**

- **데이터**: `예시 데이터 (DEMO)`는 가짜 자료입니다. 실제 업무는 `내 업무`에서 합니다.
- **표시 범위**: `전체 이벤트`는 모든 이벤트의 업무를, `현재 이벤트`는 고른 이벤트만 보여줍니다.
- **기록 관리**: `내보내기`·`가져오기`·`서버로 옮기기` 중 필요한 작업을 고릅니다. 작업을 고른 뒤에는 다시 `작업 선택`으로 돌아옵니다.

**현지 기회 조회 기간**: 30일·45일·90일을 고르고 `조회`를 누릅니다. 날짜를 직접 정하려면 `직접 입력`을 고르거나 `날짜 직접 지정`을 펼칩니다.

**상자 크기 조절**: 캘린더·현지 뉴스·검색 결과·공지 카드·오른쪽 세 상자의 **오른쪽 아래 모서리**를 끌면 가로·세로 크기를 바꿀 수 있습니다.
조회 기간 상자와 업무 편집 팝업에도 같은 손잡이가 있습니다. 버튼·날짜 입력칸 자체는 일반 입력 요소로 유지합니다.
내용이 많으면 상자 안에서 스크롤합니다. 가로 크기는 각 열의 너비 안에서 조절합니다.
맨 아래 **`상자 크기 초기화`**를 누르면 기본 배치로 돌아갑니다. 새로고침하면 기본 크기로 시작하며, 업무 기록은 바뀌지 않습니다.
큰 화면의 오른쪽은 **업무·진척 / 현지 기회 / 협업 요약**이 기본 3등분입니다.

**협업 요약에서 보는 것**: 촬영 예정·게시 예정·확인 필요 건수와, 우선 확인할 최대 3명의 **이름·채널·진행 상태·촬영일·게시일·다음 할 일**입니다.
촬영·게시 예정 건수는 조회된 협업 중 오늘 이후 날짜가 있는 미완료 건수이며, 게시 임박 목록보다 범위가 넓을 수 있습니다.
실제 자료는 인플루언서 탭의 공개 함수에서 읽습니다. **예시 데이터 (DEMO)**에서는 서로 다른 진행 상태의 가상 크리에이터 3명을 보여줍니다.
내 업무에서 자료가 없거나 연결에 실패하면 더미로 채우지 않고 상태를 안내합니다.

## 2. 가장 많이 쓰는 흐름 — 이벤트 만들기

1. 오른쪽 **현지 기회**에서 쓸 일정을 고르고 **`+ 이벤트 기획`**
   (또는 캘린더에서 일정을 누르고 같은 버튼)
2. 이름·목표일·유형을 확인하고 저장
3. **준비 업무 9단계가 날짜까지 자동으로 깔립니다**

| 단계 | 기본 시점 | 연결 탭 |
|---|---|---|
| 다낭 현지조사·타깃 가설 정리 | D-35 | 현지 시장 분석 |
| 목적·제품·타깃 확정 | D-28 | 현지 시장 분석 |
| 인플루언서 협업 제안 | D-21 | 인플루언서 마케팅 |
| 홍보 소재 초안 준비 | D-14 | 콘텐츠 스튜디오 |
| 광고 문구·소재 최종 검토 | D-7 | 콘텐츠 스튜디오 |
| 협업·채널 게시 일정 확정 | D-3 | 인플루언서 마케팅 |
| 이벤트 공개·링크 확인 | D-DAY | 콘텐츠 스튜디오 |
| 초기 반응 확인 | D+3 | KPI |
| 이벤트 회고·개선점 기록 | D+7 | KPI |

> **같은 현지 일정으로 이벤트를 두 번 만들 수 없습니다.** 이미 있으면 그 이벤트를 열어 줍니다.
> 실수로 만들었으면 `디데이 업무 ↗` → **`삭제`**로 지웁니다. 준비 업무도 함께 지워집니다.

## 3. 날마다 하는 일

- **업무 완료**: 오늘의 해야 할 일에서 **왼쪽 네모를 체크**
- **업무 수정**: 업무 이름을 누르면 창이 열림 (마감일·시간·상태·범주·메모)
- **다른 날로 미루기**: 업무 오른쪽 **`->`** 버튼
- **날짜 없는 업무**: 오늘 카드 아래 **`날짜 미정 N건`**을 펼침. **`오늘로`**를 누르면 오늘 마감이 됨

> 마감일이 지난 미완료 업무는 **오늘 목록에 계속 따라옵니다.** 놓치지 않게 하려는 것입니다.

## 4. 캘린더 보는 법

**월 / 주 / 목록** 세 가지로 볼 수 있습니다.

색으로 무엇인지 구분합니다.

| 색 | 뜻 |
|---|---|
| 금색 | **베트남 현지 일정** (공휴일·축제). 우리가 바꿀 수 없는 날 |
| 점선 금색 | **법정 공휴일(예정)** — 날짜는 맞지만 **며칠 쉬는지는 미확정** |
| 짙은 청록 | 이벤트 기준일 |
| 연한 청록 | 이벤트 일정 |
| 분홍 | 내 업무 |
| 주황 | 인플루언서 협업 |

- 하루에 최대 **4개**까지 보이고 나머지는 **`+N`**으로 묶입니다
- 여러 날 이어지는 일정은 **가로 막대**로 표시됩니다

### 점선이 무슨 뜻인가요

베트남 법은 **"설은 5일"**처럼 날짜만 정하고, **실제로 며칠 쉬는지는 해마다 총리가 공문으로 정합니다.**
그래서 2027년 설은 법상 5일인데 실제로는 **7일**(2/4~2/10)입니다.

- **점선** = 날짜는 맞음, **연휴 기간은 아직 모름**
- **실선** = 정부 공문을 확인해 등록한 **확정 일정**

**점선만 보고 캠페인 날짜를 확정하지 마세요.** 공문이 나오면 실선으로 바뀝니다.

## 5. 현지 뉴스

### 검색 (누구나, 바로)

- 한국어 버튼 6개를 누르면 **베트남어로 알아서 검색**합니다
- 직접 검색어를 넣어도 됩니다 (2~60자)
- **`자동 번역`** 스위치를 켜면 제목이 한국어로 나오고 **원문도 아래에 함께** 보입니다
- 결과는 **검증하지 않은 목록**입니다. 반드시 원문을 열어 확인하세요

### 확인된 규제·공지 (아래 색상 카드 세 개)

담당자가 **정부 원문을 직접 확인해 등록한 자료**만 올라옵니다. 지금은 법령·공지만 등록합니다.

- 세 자료를 각각 옅은 배경색으로 구분합니다. 적용 제안·운영 아이디어는 카드에 바로 보입니다.
- **`자세히 보기 · 출처와 확인 범위`**를 펼치면 전체 사실 설명·전체 제안·확인일·원문·교차 출처·등록 당시 확인한 범위를 읽을 수 있습니다.
- 이 화면은 저장된 검토 기록을 보여줍니다. 원문이 바뀌었는지 실시간으로 재검증하지는 않습니다.

> 두 영역을 섞어 보지 마세요. 위는 **참고**, 아래는 **근거**입니다.

## 6. 보고서 뽑기

**`디데이 업무 ↗` → `보고서 ↗`**

새 창에 **마케팅 이벤트 실행계획·진행현황서**가 열립니다. 위쪽 **`인쇄 · PDF로 저장`** 버튼을 누르면 PDF가 됩니다.
보고서는 서버에 저장된 **`내 업무` 이벤트**에서 엽니다. DEMO 이벤트는 브라우저에만 있으므로 보고서 버튼을 누르면 이용 범위를 안내합니다.

목적은 **이 이벤트를 위해 어떤 일을 언제까지 하고, 현재 어디까지 끝냈는지 팀이 함께 확인하는 것**입니다.
담기는 것: 개요 / 현지 일정과 적용 범위 / 진행 현황 / 업무 기간·마감·메모 / 콘텐츠 준비·직접 일정·협업 일정 / 남은 일과 확인 사항.
업무 관리 기간은 목표일과 등록 업무의 시작·마감, 직접 일정, 연결된 협업의 촬영·게시 날짜를 포함합니다. 취소 업무는 제외합니다.
자체 콘텐츠 목록은 HOME에 적힌 준비 업무의 마감일이며, 콘텐츠 스튜디오의 전체 게시 일정은 아닙니다.

담기지 않는 것과 이유:

- **성과·예산·소비자 반응** → KPI 탭이 원본입니다. 두 탭이 같은 숫자를 각각 만들면 어긋났을 때 판단할 수 없습니다. 링크만 둡니다.
- **콘텐츠의 내용·문구** → 콘텐츠 스튜디오 담당입니다. 보고서에는 **일정만** 담습니다.

## 7. 기록은 어디에 저장되나

- **이벤트·업무·일정** → 서버 DB (`instance/dashboard.sqlite3`)
- **현지 일정·뉴스** → 서버 파일 (`home/data/`)
- 화면 설정(고른 이벤트, 조회 기간 등) → 브라우저

> 다른 창에서 기록이 바뀌면 **저장을 멈추고 알려줍니다.** 덮어쓰지 않기 위해서입니다. 그때는 새로고침하세요.

**백업**: 오른쪽 위 **`내보내기`**로 파일을 받아둘 수 있고, **`가져오기`**로 되살립니다.
- **내 업무**: 가져오기는 서버 기록과 비교합니다. 없는 기록만 추가하고, 같은 기록은 건너뛰며, 같은 ID의 내용이 다르면 전체 작업을 멈춥니다. 이미 고친 기록을 옛 내용으로 덮어쓰는 복원 기능은 아닙니다.
- **예시 데이터 (DEMO)**: 확인 후 현재 브라우저의 예시 기록을 파일 내용으로 교체합니다. 실제 업무에는 적용하지 않습니다.
- **서버로 옮기기**: 예전에 브라우저에 저장했던 내 업무 백업을 서버로 옮기기 위한 안내입니다. 현재 내 업무의 가져오기와 같은 비교 절차를 씁니다. 이관이 끝났으면 매일 누를 필요가 없습니다.
내보내기는 현재 불러온 HOME 업무 기록을 보관하는 기능입니다. 뉴스·현지 일정 파일이나 다른 탭의 DB 전체를 백업하지 않습니다.

## 8. 자주 막히는 것

| 증상 | 원인과 해결 |
|---|---|
| 고친 내용이 화면에 안 보임 | 서버가 여러 개 떠 있음. `netstat -ano \| findstr :5000`으로 PID를 보고 낡은 것을 `taskkill /PID <번호> /F` |
| 새로 만든 주소가 `Not Found` | 위와 같은 원인. 서버는 `--debug`로만 켜고 `--no-reload`는 쓰지 않음 |
| `.env`를 고쳤는데 반영 안 됨 | 환경변수는 서버를 켤 때만 읽음. 껐다 켜야 함 |
| 뉴스 검색이 502 | 구글 뉴스가 짧은 간격의 연속 요청을 잠깐 막은 것. 몇 초 뒤 다시 |
| 번역 버튼이 안 보임 | `.env`에 `DEEPL_API_KEY`가 없거나 서버를 다시 켜지 않음 |

**서버 켜는 명령** (cmd)

```
.venv\Scripts\python.exe -m flask --app app run --debug
```

**공휴일 연도 더 받기**

```
flask --app app home holidays-sync --from 2037 --to 2040
```

- **성과 분석·예산** → KPI 탭
- **콘텐츠 제작·문구 검수** → 콘텐츠 스튜디오
- **인플루언서 섭외·단가** → 인플루언서 마케팅
- **경쟁사·시장 분석** → 현지 시장 분석
- **AI 추천·자동 브리핑** → 넣지 않기로 팀에서 정했습니다. 판단은 사람이 합니다

## 10. 시연 순서 (5분)

보여줄 순서입니다. 이 순서대로 하면 이 탭이 무엇을 하는 곳인지 전달됩니다.

1. **문제 제기** — "베트남 공휴일을 모르면 캠페인 날짜를 못 잡습니다."
   달력에서 **2027년 2월**로 넘겨 설 연휴(2/4~2/10)를 보여줍니다.
   이어서 **2029년, 2035년**으로 넘깁니다. *"법정 공휴일은 2036년까지 미리 들어와 있습니다."*
2. **점선 설명** — *"점선은 날짜만 확정이고 연휴 기간은 정부 공문이 나와야 압니다.
   추측으로 확정처럼 보이게 하지 않았습니다."*
3. **역산 기획** — 현지 기회에서 일정을 고르고 **`+ 이벤트 기획`**.
   *"목표일만 정하면 준비 업무 9단계가 날짜까지 자동으로 깔립니다."*
4. **오늘 할 일** — 업무를 하나 체크하고 진척도가 올라가는 것을 보여줍니다.
5. **현지 뉴스** — 버튼 하나로 베트남 기사를 불러오고 **자동 번역**을 켭니다.
   *"번역문 아래에 원문을 같이 둡니다. 번역은 틀릴 수 있어서입니다."*
6. **보고서** — `디데이 업무 ↗` → `보고서 ↗` → **`인쇄 · PDF로 저장`**.
   *"이벤트 상황을 문서 한 장으로 팀에 넘깁니다."*

### 받을 만한 질문과 답

| 질문 | 답 |
|---|---|
| 왜 AI 추천이 없나요 | 팀에서 빼기로 정했습니다. 틀린 추천은 일정 사고로 이어집니다. 판단은 사람이 합니다 |
| 왜 성과 지표가 없나요 | KPI 탭이 원본입니다. 두 탭이 같은 숫자를 각각 만들면 어긋났을 때 판단할 수 없습니다 |
| 과일 시즌 같은 건 왜 없나요 | 세 번 조사했는데 정부 자료에 수확 시기가 없고 공개 자료는 서로 어긋났습니다. 근거 없는 자료는 올리지 않습니다 |
| 공휴일이 틀리면요 | 법정 공휴일은 점선, 공문으로 확인한 것만 실선입니다. 확인한 자료에는 출처를 함께 보관합니다 |
| 다음은 뭘 하나요 | 화면 정리 후 2주 실사용입니다. 더 넣을 기능은 실제로 써 보고 정합니다 |

## 11. 자료는 어디서 왔고, 어떻게 정리했나요?

**발표할 때는 이렇게 설명하면 됩니다.**

> 검색 뉴스는 외부 기사 목록을 자동으로 가져와 중복을 줄이고 날짜순으로 보여줍니다.
> 확인된 규제·공지는 출처와 검토 메모를 붙여 등록한 별도 자료입니다.
> 운영 아이디어는 자료에 함께 적어둔 제안이며, 화면을 열 때 AI가 새로 만들지 않습니다.

### A. 검색 뉴스가 화면에 오는 순서

1. 사용자가 주제 버튼을 누릅니다. 버튼마다 미리 적어둔 **베트남어 검색어**를 구글 뉴스에 보냅니다.
   VnExpress 영문 경제·종합 목록에서는 주제별 영어 낱말이 제목이나 소개문에 있는 기사를 고릅니다.
   검색어를 직접 입력하면 **구글 뉴스만** 검색합니다.
2. RSS라는 기사 목록을 받습니다. 가져오는 주소는 아래와 같습니다.
   - 구글 뉴스: `https://news.google.com/rss/search` (베트남 언어·지역 설정)
   - VnExpress 경제: `https://e.vnexpress.net/rss/business.rss`
   - VnExpress 종합: `https://e.vnexpress.net/rss/news.rss`
3. **제목·언론사·발행일·원문 주소**를 뽑습니다. 제목이나 안전한 HTTPS 주소가 없는 항목은 제외합니다.
   구글 제목 끝에 언론사가 반복되면 떼어내 언론사 칸에 표시합니다.
4. 제목에서 공백·기호·대소문자 차이를 줄여 같은 제목을 합칩니다. 서로 다르게 쓴 제목까지 같은 기사로 판정하지는 않습니다.
5. 발행일이 최신인 순서로 정렬해 **최대 12개** 보여줍니다. 날짜를 읽지 못한 자료는 날짜를 만들어 넣지 않습니다.
6. 자동 번역을 켰다면 제목을 **DeepL**에 보내 번역합니다. 번역문 아래 원문도 보여줍니다.
   기사 본문 요약이나 자동 사실 판정은 하지 않습니다. 검색 결과는 DB·JSON에 저장하지 않습니다.

여기서 **정리(정제)**는 목록 형식 통일·중복 줄이기·정렬입니다. **사실 검증 완료라는 뜻은 아닙니다.**
구현 위치: [뉴스 검색 코드](news_search.py), [번역 코드](translate.py).

### C. ‘확인했다’는 것은 어떤 절차인가요?

등록 도구가 지원하는 절차는 **원문 읽기 → 별도 출처와 대조 → 사실·제안·한계 작성 → 형식 검사 → 등록 승인**입니다.

- 원문에서 이름·날짜·지역·적용 대상을 확인합니다. 다른 작성자나 취재팀의 자료와 비교합니다.
  같은 원문을 다시 올린 글이나 같은 기관 문서 두 개만으로 독립 교차 확인을 했다고 보지 않습니다.
- 사실 설명, 우리에게 주는 제안, 확인하지 못한 내용을 나눠 적습니다. 교차 자료마다 무엇을 뒷받침하는지도 적습니다.
- 프로그램은 필수 내용·날짜 형식·중복 ID·서로 다른 HTTPS 주소 2개 이상·원문/교차 출처 역할 등을 검사합니다.
  **주소 두 개가 있다는 것만으로 사실이나 출처 독립성이 자동 검증되지는 않습니다.**
- 승인 대기 상태로 등록한 뒤, 확인 절차를 거쳐 승인된 자료만 화면에 보여줍니다.

`news_import.py`의 본문 읽기 도구는 HTML 태그와 스크립트·스타일 등을 걷어내 글자를 보여줍니다.
메뉴 글자도 섞일 수 있어 담당자가 원문을 읽어야 합니다. 이 도구 자체가 요약하거나 사실을 인증하지 않습니다.
PDF 자료를 자동으로 읽고 법률 판단까지 해주는 기능도 아닙니다.

### D. AI가 정확히 무엇을 했나요?

현재 코드에는 뉴스 수집·등록 과정에서 생성형 AI를 호출하는 부분이 없습니다.
검색·필터·중복 제거는 위 규칙대로 실행되고, 제목 번역은 DeepL을 이용합니다.
사실 요약과 운영 제안은 저장된 문구를 읽습니다. 첫 문장 미리보기도 마침표 등으로 나누는 표시 처리입니다.

AI 도구가 개발이나 초안 작성에 쓰였을 수는 있지만, **각 자료를 처음 찾은 AI 이름·검색 프롬프트·전체 실행 기록은 현재 자료 파일에 없습니다.**
따라서 ‘특정 AI가 모든 자료를 자동 수집·검증했다’고 설명하지 않습니다.
확인 가능한 것은 코드·저장된 출처·대조 메모·등록 상태이며, 과거 사람의 원문 확인 행동까지 이 파일만으로 증명할 수는 없습니다.

### E. 달력·협업·업무 기록도 기억해두세요

## 12. 발표 전에 이해할 내용 — 쉬운 브리핑

**핵심:** HOME은 현지 일정에 맞춰 이벤트 준비 업무를 짜고, 진행 상황을 관리하는 탭입니다.
보고서는 그 내용을 팀이 함께 읽는 실행계획·진행현황서입니다.

### 공공부문이라는 말은 왜 붙었나요?

정부기관·공립기관 등에 적용되는 휴무 기준이라는 뜻입니다. 모든 민간 업체가 같은 기간에 쉰다는 뜻으로 넓혀 말하지 않으려고 표시합니다.
[정부 안내](https://xaydungchinhsach.chinhphu.vn/de-xuat-2-phuong-an-nghi-tet-nguyen-dan-2027-tet-dinh-mui-11926080513033257.htm)는 공공부문 기준과 그 밖의 근로자에 대한 사업장별 선택 방식을 구분합니다.
현지 공장·배송업체·매장이 실제 언제 쉬는지는 거래처에 따로 확인합니다.

발표에서는 **“공식 자료의 적용 대상을 함께 표시해서, 모든 회사가 같은 기간 쉰다고 오해하지 않도록 했습니다”**라고 말하면 됩니다.

### 보고서는 어떤 판단을 돕나요?

| 구성 | 읽는 사람이 답을 얻는 질문 |
|---|---|
| 개요 | 무슨 제품을, 누구에게, 어떤 채널로 준비하나? |
| 현지 일정과 적용 범위 | 일정에 영향을 주는 현지 행사가 있고, 누구에게 적용되나? |
| 진행 현황 | 얼마나 끝났고 지연·보류·날짜 미정 업무는 몇 개인가? |
| 업무 일정 | 어떤 일을 언제부터 언제까지 하나? 메모는 무엇인가? |
| 콘텐츠·직접 일정·협업 | 콘텐츠 준비, 촬영·게시, 직접 입력한 일정은 언제인가? |
| 남은 일과 팀 확인 사항 | 앞으로 무엇을 하고, 막힌 것은 무엇을 확인해야 하나? |

목표일 이후의 후속 업무도 포함하므로 ‘준비 기간’ 대신 ‘업무 관리 기간’이라고 씁니다.
마감일 없는 업무와 보류 업무를 드러내고, 입력된 회고는 다음 회차 메모로 보여줍니다.
현재 HOME에는 별도의 업무 담당자 입력칸·정량 성과 목표 입력칸이 없어 보고서에 임의로 채우지 않습니다.
향후 담당자·의사결정 책임자·목표 지표가 필요해지면 입력 항목과 다른 탭의 공개 범위를 먼저 합의합니다.

### 기록 관리 버튼은 언제 쓰나요?

- **내보내기 = 보관용 파일 만들기.** 큰 수정을 하기 전이나 시연 전에 기록을 받아둡니다.
- **가져오기 = 보관 파일을 현재 기록과 비교해 추가하기.** 내 업무에서 없는 기록을 다시 넣을 때 씁니다. 이미 수정된 기록을 강제로 과거 상태로 돌리지는 않습니다.
- **서버로 옮기기 = 예전 브라우저 기록을 서버에 입주시키기.** 이미 옮겼다면 평소에는 쓸 일이 거의 없습니다.

내 업무에서 가져오기와 서버로 옮기기는 현재 같은 안전한 절차를 씁니다. 이름이 다른 것은 예전 저장 방식에서 넘어오는 안내를 남겨둔 것입니다.
예시 모드의 가져오기는 브라우저 예시를 교체하므로 실제 업무와 구분해서 설명합니다.

### 협업 요약은 무엇을 보여주면 좋나요?

HOME에서는 **협업을 실행할 때 놓치면 안 되는 일정과 다음 행동**을 보여줍니다.
이름·채널·현재 상태·확정 촬영일·게시 예정일·확인할 일을 보고, 자세한 내용은 인플루언서 탭으로 이동합니다.
현재 구현도 이 항목을 사용합니다. 예시 모드의 가상 자료는 실제 연동 자료의 개수나 성공 여부를 증명하지 않습니다.

진혁 담당자와 다음 항목을 합의합니다. 여기서 작성한 것은 협의할 내용이며 실제로 메시지를 보내지는 않았습니다.

| 협의할 것 | 쉽게 말하면 |
|---|---|
| 행사·협업 ID의 연결 | HOME의 어떤 이벤트에 누구의 협업을 붙일지 같은 번호 체계를 확인합니다. 현재 공개 함수의 협업 ID는 인플루언서 ID입니다. |
| 날짜의 의미 | 촬영 가능일과 확정 촬영일을 구분하고, 게시 예정일이 미정일 때의 표시를 정합니다. |
| 상태와 다음 행동 | 계약 확정·촬영 완료·게시 완료의 판단 기준과 알림의 우선순위를 맞춥니다. |
| 목록과 총계 | 현재 할 일 알림은 최대 10개를 받습니다. 확인 필요 숫자를 전체 미처리 건수로 사용할 수 있는지 합의가 필요합니다. |
| 빈 목록과 오류 | 현재 공개 함수는 내부 오류에도 빈 목록을 반환할 수 있습니다. 자료 없음과 연결 실패를 구분할 수 있는 응답이 필요합니다. |
| 이동 주소와 갱신 | 누르면 해당 협업을 바로 열 수 있는지, 언제 수정된 자료인지, HOME이 언제 다시 읽을지 정합니다. |
| 수정 책임과 DEMO | 원본 수정은 인플루언서 탭에서 하고, 예시 표시를 반드시 전달받습니다. |

팔로워·단가·성과는 상세 탭이나 KPI에서 확인합니다. HOME 요약은 촬영·게시와 준비 업무를 연결하는 데 집중합니다.

### 내용을 익힌 뒤 쓸 1분 브리핑 초안

> HOME은 베트남 현지 일정에 맞춰 이벤트 준비 업무를 계획하고 진행 상황을 관리하는 탭입니다.
> 현지 일정을 보고 목표일을 정하면 준비 업무 9단계가 날짜와 함께 만들어집니다.
> 오늘 할 일과 완료율로 진행 상황을 확인하고, 협업 요약에서 촬영·게시 일정과 다음 행동을 봅니다.
> 뉴스 검색 결과와 출처를 확인해 등록한 공지는 나눠 보여줍니다. 휴무 일정에는 공공부문처럼 적용 대상도 표시합니다.
> 마지막으로 이벤트 실행계획·진행현황서를 출력해 팀이 해야 할 일과 남은 일을 함께 확인할 수 있습니다.
