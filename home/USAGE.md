# HOME 탭 사용 설명

> 담당: 정주연 · 2026-10-27 실제 업무 전용 화면 기준
> 개발 내용과 변경 이력은 [README.md](README.md)에 있습니다.

## 1. 이 탭의 목적

**베트남 현지 일정에 맞춰 이벤트 준비 업무를 짜고, 진행 상황을 관리하는 탭입니다.**
목표일을 정하면 준비 업무 9단계를 날짜와 함께 만들고, 오늘 할 일과 촬영·게시 일정을 확인합니다.
상단 제목은 HOME으로 고정합니다. 오른쪽 시계에서 한국·베트남의 시간과 날짜를 나란히 봅니다. 업무 기준은 한국 시간입니다.

## 2. 화면 구성

| 위치 | 이름 | 하는 일 |
|---|---|---|
| 왼쪽 위 | 월간 일정 / 주간 일정 / 디데이 업무 관리 | 세 책갈피로 월 달력·시간별 주간 일정·간트 차트를 전환 |
| 왼쪽 아래 | 현지 뉴스 | 검색 결과와 출처를 기록해 등록한 규제·공지 |
| 오른쪽 위 | 이벤트 업무 진척도 / 오늘의 업무 | 선택한 이벤트의 완료율, 오늘·지연 업무, 내일 미리보기 |
| 오른쪽 가운데 | 베트남 주요 일정 | 조회 기간의 현지 일정을 보고 이벤트 준비 시작 |
| 오른쪽 아래 | 인플루언서 협업 요약 | 등록·제안·회신·확정 인원과 확인할 일 |

데이터는 서버에 저장된 실제 업무만 사용합니다. 데이터 모드와 기록 관리 메뉴는 없습니다.
상자 오른쪽 아래를 끌면 크기를 조절합니다. 각 규제·공지 카드는 크기 조절 대상에서 제외했습니다.
상자 크기는 화면에서만 바뀌며, 새로고침하면 기본 크기로 돌아갑니다.
큰 카드 5개에는 바깥 테두리만 표시합니다. 내부 뉴스 카드와 버튼의 테두리를 모두 복구한 것은 아닙니다.
베트남 주요 일정의 **일정 상세**를 누르면 기간·적용 대상·안내·근거 자료를 나눠 볼 수 있습니다.
출처 링크는 이 상세창에서 확인하고, 원문 기간·확인 범위는 펼쳐서 읽습니다. 목록에서는 출처와 확인 날짜를 숨깁니다.
인플루언서 협업 요약의 **인플루언서 마케팅 ↗**은 해당 탭으로 이동하는 링크입니다.

## 3. 캘린더

- **월간 일정 / 주간 일정** 책갈피로 보기를 바꿉니다. 별도의 월·주 버튼과 이벤트 필터는 없습니다.
- 캘린더와 오늘의 업무에는 전체 이벤트의 기록을 표시합니다. 디데이 업무 관리에서 고른 이벤트는 간트·보고서·진척도의 기준입니다.
- 큰 날짜 제목 옆의 좌우 화살표로 이전·다음 월 또는 주로 이동합니다.
- 월 보기는 그달에 필요한 4~6주만 표시합니다. 월요일부터 일요일까지 같은 높이의 행을 사용합니다.
- 공간에 맞춰 하루 2~4줄(기간 막대 포함)을 사용하며 나머지는 **+N개 더보기**로 모읍니다. 더보기를 누르면 그날의 전체 일정과 상세 보기 버튼이 나타납니다. 좁은 화면은 최대 3줄이며, 카드가 작아지면 달력 안에서 스크롤합니다.
- 일정 제목을 누르면 업무 수정·현지 일정 상세·디데이 업무 관리를 엽니다. 협업은 상세창에서 원본 링크를 누릅니다. 긴 제목은 마우스를 올리면 전체 이름을 확인할 수 있습니다.
- 오늘은 녹색 숫자 배지, 선택한 날은 옅은 배경으로 구분합니다. 완료 업무는 취소선 없이 완료 표시를 사용합니다. 상태는 기존 기록을 따르고, 지연 표시는 미완료 업무의 마감일이 지난 경우에만 붙입니다. 현지 일정에 업무 상태를 임의로 붙이지 않습니다.
- 주 보기는 **시간표 / 목록**으로 바꿉니다. 처음에 시간 지정 업무가 없으면 목록을 보여주며, 직접 고른 방식은 브라우저에 보관합니다.
- 시간표는 날짜 헤더·종일 일정·시간 영역으로 나누고 08시부터 보입니다. 스크롤하면 00~24시 전체를 확인합니다. 작은 카드에서는 08~20시를 한 번에 담지 못할 수 있으며 안쪽에서 스크롤합니다.
- 시간표 기준은 **한국 시간(KST)**입니다. 오늘 열의 가는 선은 실제 KST 현재 시각이고, 다른 주에는 나오지 않습니다. 날짜와 종일 영역은 스크롤해도 위쪽에 남습니다.
- 현재 업무에 저장된 시간은 **마감 시각 하나뿐**입니다. 시간 카드는 `09:30 마감`처럼 표시하며, 카드 높이는 읽기 위한 크기입니다. 작업 시간이나 임의의 종료 시각을 뜻하지 않습니다. 가까운 시각의 카드가 겹치면 옆으로 나눕니다.
- 종일 일정이 많으면 더보기로 전체를 확인합니다. 목록은 일주일의 종일·시간 지정 일정을 날짜별로 모두 보여줍니다. 제목을 누르면 기존 상세·업무 수정 기능을 엽니다.
- 날짜를 누르면 오른쪽 업무 목록이 그날 기준으로 바뀝니다. 오른쪽의 **오늘로**로 현재 업무로 돌아옵니다.
- 금색은 현지 일정, 청록 계열은 이벤트, 업무·협업은 기존 범주 색을 유지합니다.
- **점선**은 법정일 기준 자동 자료이며 실제 연휴 기간은 별도 확인이 필요합니다.
- **공공부문**은 정부·공립기관 등을 기준으로 한 휴무 일정이라는 뜻입니다. 민간 거래처의 실제 운영일은 따로 확인합니다.
- 주간 날짜 제목은 연도를 함께 표시합니다. 한국 시간으로 자정이 지나면 오늘 날짜·업무·D-day가 갱신됩니다. 직접 골라 둔 다른 날짜는 유지합니다.

## 4. 이벤트 만들기와 업무 관리

1. 베트남 주요 일정에서 **+ 이벤트 기획**을 누르거나, 디데이 업무 관리에서 **+ 새 이벤트**를 누릅니다.
2. 이름·목표일·제품·타깃·채널을 확인하고 저장합니다.
3. 기본 준비 업무 9단계가 날짜와 함께 생성됩니다.

| 업무 | 기본 시점 |
|---|---|
| 다낭 현지조사·타깃 가설 정리 | D-35 |
| 목적·제품·타깃 확정 | D-28 |
| 인플루언서 협업 제안 | D-21 |
| 홍보 소재 초안 준비 | D-14 |
| 광고 문구·소재 최종 검토 | D-7 |
| 협업·채널 게시 일정 확정 | D-3 |
| 이벤트 공개·링크 확인 | D-DAY |
| 초기 반응 확인 | D+3 |
| 이벤트 회고·개선점 기록 | D+7 |

디데이 업무 관리의 큰 제목은 현재 이벤트명입니다. 옆의 작은 화살표를 누르면 진행 중인 이벤트를 고릅니다.
제목 옆 선택 버튼에서 진행 중인 이벤트와 지난 이벤트를 구분해 고릅니다. 완료·보관된 이벤트도 여기서 다시 열 수 있습니다.
이벤트명 아래 상태·행사일·디데이를 확인합니다. 다음 줄은 완료율과 완료 업무 수이며 오른쪽 진척도 위젯과 같은 계산을 사용합니다. 취소 업무는 완료율에서 제외합니다.
새 이벤트는 녹색 버튼, 보고서·수정·회고 관리는 옆 버튼으로 엽니다. **더보기**에서 복제·삭제를 고르며 삭제는 확인창을 거칩니다. 더보기는 Esc 또는 바깥 클릭으로 닫습니다.
차트는 업무명·시작일·마감일·상태·기간 막대를 같은 행에 보여줍니다. 위쪽 월·날짜 눈금과 막대는 같은 날짜 간격을 사용합니다. 시작일과 마감일을 모두 포함하며 같은 날 시작·마감한 업무도 하루 막대로 표시합니다.
시작일이 없는 업무의 **별표(*) 날짜는 기존 자동 기준일**입니다. 앞 업무 마감일(첫 업무는 마감 3일 전)을 사용하며 기록에 새 시작일을 저장하지 않습니다. 시작일 없는 취소 업무는 마감일 점만 표시합니다.
업무명은 가로 스크롤에도 고정되고, 표 머리글은 세로 스크롤에도 남습니다. 좁은 카드에서는 날짜·상태를 업무명 아래와 상세창에서 확인합니다. 날짜 미정·취소 업무도 목록에 남습니다.

- 업무 이름 또는 막대를 누르면 마감일·시간·상태·범주·메모를 수정합니다. 마우스를 올리면 전체 업무명·날짜·상태·기존 메모를 확인합니다.
- 진행 중은 짙은 녹색, 완료는 회녹색, 예정은 베이지, 미완료 기한 초과는 붉은 갈색, 취소는 중성 점선으로 구분합니다. 보류는 줄무늬와 상태 배지를 사용합니다. 완료에 취소선을 넣거나 날짜만 보고 완료 처리하지 않습니다.
- 회고 관리를 누르면 팝업에서 상태와 잘된 점·문제와 원인·다음 회차 개선을 적고 저장합니다.
- 같은 현지 일정으로 만든 이벤트가 이미 있으면 기존 이벤트를 열어 중복 생성을 막습니다.

## 5. 오늘의 업무와 내일 미리보기

오늘 마감인 업무와 지난 미완료 업무가 표시됩니다. 체크하면 완료 상태와 진척도가 서버에 저장됩니다.
업무 오른쪽 화살표로 마감일을 미룰 수 있습니다. 업무 행의 배경색은 완료·지연 여부와 관계없이 넣지 않습니다.

아래 **내일의 업무**는 내일 마감인 미완료 업무를 최대 3개 미리 보여줍니다. 더 있으면 내일 전체 보기를 누릅니다.
오늘 업무가 없으면 내일 미리보기 공간이 커집니다. 날짜 미정 업무는 별도 펼침 목록에서 확인합니다.

## 6. 현지 뉴스

주제 버튼 또는 직접 검색어로 기사를 찾습니다. 검색·번역 중에는 회전 표시와 진행 안내가 나타납니다.
검색 전에는 작은 빈 상자와 제목 옆 안내문을 보여주고, 검색을 시작하면 결과 공간이 넓어집니다.
자동 번역은 제목만 번역하며, 번역된 제목은 굵게 표시하고 원문과 언론사·날짜를 아래에 둡니다.
검색 결과는 자동 수집 목록입니다. 사실 판단이나 업무 적용 전에는 원문을 확인합니다.

등록된 규제·공지 세 카드는 제목을 누르면 원문으로 이동합니다. 제목 아래 지역·발행일과 짧은 요약·운영 아이디어를 보여줍니다.
**자세히 보기 · 출처와 확인 범위**를 펼치면 전체 내용, 원문과 교차 출처, 등록 당시 확인한 범위를 읽습니다.
화면의 짧은 미리보기는 글자 수를 줄인 표시이며 새로운 AI 요약을 생성하지 않습니다.

## 7. 보고서와 협업 요약

디데이 업무 관리에서 이벤트를 고르고 **보고서 ↗ → 인쇄 · PDF로 저장**을 누릅니다.
문서의 목적은 **어떤 일을 언제까지 하고, 현재 어디까지 끝냈는지 팀이 함께 확인하는 것**입니다.
개요·현지 일정 적용 범위·진척·업무 기간/메모·직접 일정·콘텐츠 준비와 협업 일정·남은 일·회고를 담습니다.
자체 콘텐츠 목록은 HOME 준비 업무의 마감일이며 콘텐츠 스튜디오의 전체 게시 일정은 아닙니다.
예산·성과는 KPI 탭, 콘텐츠의 내용·문구는 콘텐츠 스튜디오가 원본입니다.

협업 요약은 인플루언서 탭의 **요약 화면을 작게 보여주는 곳**입니다.
진혁 담당의 `get_home_summary()`에서 **실제 자료** 결과를 그대로 받아 표시합니다.

- **등록 → 제안 보냄 → 회신 받음 → 확정** 인원을 보여줍니다. 확정에는 계약 확정·촬영 완료·게시 완료가 포함됩니다.
- 단계별 인원에는 같은 사람이 여러 번 포함될 수 있으므로 네 숫자를 더해 전체 인원을 계산하지 않습니다.
- **확인할 일**에는 회신 확인·촬영일 확정 등 해당 건수가 있는 종류만 표시합니다. 합계는 사람 수가 아니라 할 일의 건수입니다.
- 정상 조회에서 실제 기록이 없으면 0명과 등록 기록 없음 안내가 나옵니다. 조회 실패는 숫자 대신 오류 안내가 나옵니다.
- DEMO는 합산하지 않습니다. 요약은 고른 이벤트나 현지 일정 조회 기간과 관계없이 전체 실제 자료 기준이며, 계산 기준일을 함께 표시합니다.

두 화면의 숫자를 비교할 때는 인플루언서 요약도 **전체 이벤트·실제 데이터만** 조건으로 맞춥니다.

원본 수정과 자세한 확인은 **인플루언서 마케팅 ↗**에서 합니다. 새로고침하면 HOME에도 다시 반영됩니다.
캘린더의 촬영·게시 일정 연결은 기존 공개 함수로 계속 가져옵니다.

## 8. 저장과 오류

업무는 서버 SQLite DB에 저장됩니다. 화면에서 기록을 내보내거나 가져오는 기능은 제거했습니다.
화면 선택·번역 설정 등은 브라우저에 보관합니다. 예전 브라우저 기록과 이미 받은 백업 파일은 자동으로 지우지 않습니다.
다른 창에서 바뀐 기록을 덮어쓰려 하면 저장을 멈추고 알립니다. 새로고침 후 다시 확인합니다.
뉴스·번역·협업 연결이 실패하면 오류 또는 원문을 표시합니다. 실제 자료가 없는 곳에 가상 자료를 채우지 않습니다.
로그인과 계정별 저장은 아직 없습니다. 로그인과 백업은 서로 다른 기능이며 계정 기능이 백업을 대신하지는 않습니다.

## 9. 서버 실행과 확인

담당자는 cmd를 사용합니다. 기존 프로젝트 서버를 먼저 확인·종료한 뒤 하나만 켭니다.

~~~cmd
.venv\Scripts\python.exe -m flask --app app run --debug
~~~

--no-reload는 사용하지 않습니다. 기존 설정은 Flask 기본 방식으로 적용합니다. 키를 출력하거나 파일을 공유하지 않습니다.
화면 수정이 바로 보이지 않으면 Ctrl+F5로 새로고침합니다. 새 창에서 작업해도 같은 서버 기록을 사용합니다.

## 10. 5분 시연 순서

1. HOME 제목과 두 나라의 날짜·시간을 설명합니다.
2. 베트남 주요 일정에서 날짜를 고르고 이벤트를 만듭니다.
3. 준비 업무 9단계와 목표일 역산을 보여줍니다.
4. 오늘 업무를 완료하고 진척도·간트 변화, 내일 업무 미리보기를 확인합니다.
5. 뉴스 검색·제목 번역·등록 공지의 원문과 확인 범위를 보여줍니다.
6. 회고 팝업과 실행계획·진행현황서를 보여줍니다.

## 11. 자료는 어디서 왔고, 어떻게 정리했나요?

**발표할 때는 이렇게 설명하면 됩니다.**

> 검색 뉴스는 외부 기사 목록을 자동으로 가져와 중복을 줄이고 날짜순으로 보여줍니다.
> 확인된 규제·공지는 출처와 검토 메모를 붙여 등록한 별도 자료입니다.
> 운영 아이디어는 자료에 함께 적어둔 제안이며, 화면을 열 때 AI가 새로 만들지 않습니다.

### A. 검색 뉴스가 화면에 오는 순서

1. 사용자가 주제 버튼을 누릅니다. 버튼마다 미리 적어둔 **베트남어 검색어**를 구글 뉴스에 보냅니다.
   VnExpress 영문 경제·종합 목록에서는 주제별 영어 낱말이 제목이나 소개문에 있는 기사를 고릅니다.
   검색어를 직접 입력하면 **구글 뉴스만** 검색합니다.
2. RSS라는 기사 목록을 받습니다. 가져오는 주소는 아래와 같습니다.
   - 구글 뉴스: `https://news.google.com/rss/search` (베트남 언어·지역 설정)
   - VnExpress 경제: `https://e.vnexpress.net/rss/business.rss`
   - VnExpress 종합: `https://e.vnexpress.net/rss/news.rss`
3. **제목·언론사·발행일·원문 주소**를 뽑습니다. 제목이나 안전한 HTTPS 주소가 없는 항목은 제외합니다.
   구글 제목 끝에 언론사가 반복되면 떼어내 언론사 칸에 표시합니다.
4. 제목에서 공백·기호·대소문자 차이를 줄여 같은 제목을 합칩니다. 서로 다르게 쓴 제목까지 같은 기사로 판정하지는 않습니다.
5. 발행일이 최신인 순서로 정렬해 **최대 12개** 보여줍니다. 날짜를 읽지 못한 자료는 날짜를 만들어 넣지 않습니다.
6. 자동 번역을 켰다면 제목을 **DeepL**에 보내 번역합니다. 번역문 아래 원문도 보여줍니다.
   기사 본문 요약이나 자동 사실 판정은 하지 않습니다. 검색 결과는 DB·JSON에 저장하지 않습니다.

여기서 **정리(정제)**는 목록 형식 통일·중복 줄이기·정렬입니다. **사실 검증 완료라는 뜻은 아닙니다.**
구현 위치: [뉴스 검색 코드](news_search.py), [번역 코드](translate.py).

### C. ‘확인했다’는 것은 어떤 절차인가요?

등록 도구가 지원하는 절차는 **원문 읽기 → 별도 출처와 대조 → 사실·제안·한계 작성 → 형식 검사 → 등록 승인**입니다.

- 원문에서 이름·날짜·지역·적용 대상을 확인합니다. 다른 작성자나 취재팀의 자료와 비교합니다.
  같은 원문을 다시 올린 글이나 같은 기관 문서 두 개만으로 독립 교차 확인을 했다고 보지 않습니다.
- 사실 설명, 우리에게 주는 제안, 확인하지 못한 내용을 나눠 적습니다. 교차 자료마다 무엇을 뒷받침하는지도 적습니다.
- 프로그램은 필수 내용·날짜 형식·중복 ID·서로 다른 HTTPS 주소 2개 이상·원문/교차 출처 역할 등을 검사합니다.
  **주소 두 개가 있다는 것만으로 사실이나 출처 독립성이 자동 검증되지는 않습니다.**
- 승인 대기 상태로 등록한 뒤, 확인 절차를 거쳐 승인된 자료만 화면에 보여줍니다.

`news_import.py`의 본문 읽기 도구는 HTML 태그와 스크립트·스타일 등을 걷어내 글자를 보여줍니다.
메뉴 글자도 섞일 수 있어 담당자가 원문을 읽어야 합니다. 이 도구 자체가 요약하거나 사실을 인증하지 않습니다.
PDF 자료를 자동으로 읽고 법률 판단까지 해주는 기능도 아닙니다.

### D. AI가 정확히 무엇을 했나요?

현재 코드에는 뉴스 수집·등록 과정에서 생성형 AI를 호출하는 부분이 없습니다.
검색·필터·중복 제거는 위 규칙대로 실행되고, 제목 번역은 DeepL을 이용합니다.
사실 요약과 운영 제안은 저장된 문구를 읽습니다. 첫 문장 미리보기도 마침표 등으로 나누는 표시 처리입니다.

AI 도구가 개발이나 초안 작성에 쓰였을 수는 있지만, **각 자료를 처음 찾은 AI 이름·검색 프롬프트·전체 실행 기록은 현재 자료 파일에 없습니다.**
따라서 ‘특정 AI가 모든 자료를 자동 수집·검증했다’고 설명하지 않습니다.
확인 가능한 것은 코드·저장된 출처·대조 메모·등록 상태이며, 과거 사람의 원문 확인 행동까지 이 파일만으로 증명할 수는 없습니다.

### E. 달력·협업·업무 기록도 기억해두세요

| 항목 | 실제 경로와 처리 |
|---|---|
| 사람이 등록한 현지 일정 | `home/data/events.json`을 기간별로 읽습니다. 정부·기관 원문과 교차 자료가 항목별로 보관돼 있습니다. 보류 후보는 달력에 올리지 않습니다. |

## 12. 짧은 발표 문장

> HOME은 베트남 현지 일정에 맞춰 이벤트 준비 업무를 계획하고 진행 상황을 관리하는 탭입니다. 목표일을 정하면 준비 업무가 날짜와 함께 만들어집니다. 오늘·내일의 업무와 촬영·게시 일정을 확인하고, 실행계획·진행현황서를 팀에 공유합니다. 자료 조사와 정리에는 AI를 활용했으며 원문·교차 근거·확인 한계를 함께 보관합니다.
