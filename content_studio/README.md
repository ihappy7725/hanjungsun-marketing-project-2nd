# 콘텐츠 스튜디오

> 한정선 제품 정보와 베트남 현지 일정을 바탕으로 **포스터·카드뉴스·영상**을 대화로 만들고, 가운데 화면에서 바로 고치는 탭입니다.
> 

**문서 상태: 개발 중.** 화면과 흐름은 시연 데이터로 동작합니다. 이 문서는 지금 구현된 것과 앞으로 만들 것을 함께 적습니다.

| 표시 | 뜻 |
| --- | --- |
| ✅ | 구현됨 (시연 데이터·간이 방식 포함) |
| 🛠 | 구현돼 있지만 이 문서 기준으로 **바꿀 예정** |
| 📝 | 설계만 있음 (아직 구현 전, 코드 없음) |

| 담당 | 맡은 영역 |
| --- | --- |

## 1. 이 탭에서 하는 일

탭 위쪽의 작은 탭 세 개로 나뉩니다. 각 탭 안에서 처음부터 끝까지 한 화면에서 끝냅니다.

| 탭 | 하는 일 | 결과물 | 연동 | 담당 |
| --- | --- | --- | --- | --- |
| **포스터** | 목적·제품·문구·분위기·규격을 말하면 AI가 문구와 이미지를 만들고, 요소(레이어)별로 나눠 구성. 대화나 직접 수정으로 다듬기 | PNG/JPG, (검증 후) SVG·Figma | GPT(OpenAI), Figma | 희주 |
| **카드뉴스** | 받은 템플릿과 **기본 프롬프트**에 맞춰 인스타그램 게시글용 카드뉴스 생성·수정 | PNG 여러 장 (4:5·1:1) | GPT 또는 Canva | 희주 |
| **영상** | 요청대로 Higgsfield 프롬프트 초안을 짜고, **사용자 검토·승인 후** 영상 생성 | 영상(mp4) | Higgsfield | 유진 |

### 사용 흐름

```
① 탭 고르기 (포스터 / 카드뉴스 / 영상)
        ↓
② 첫 화면: 내 작업을 가로로 넘겨 보기 → 이어서 열기
          또는 아래 "지금 만들면 좋은 것"(기념일·제철·신메뉴 추천) 카드 누르기
          또는 "새로 만들기"
        ↓
③ 작업 화면: 가운데 결과물 + 아래 한 줄 입력 (배경 제거는 위쪽 [✂️ 배경 제거] 버튼, 5장)
   ├─ 포스터·카드뉴스: 가운데에서 직접 고치기 / ↶ ↷ 되돌리기·다시하기 / 내보내기 (말로 고치기는 준비 중)
   └─ 영상: ① 초안(장면 구성) → ② 프롬프트 검토·수정 → ③ "이 프롬프트로 영상 만들기" → 결과 재생
        ↓
④ "☰ 이전 작업"에서 언제든 이어서 하기
```

## 3. 포스터 탭 (희주)

### 3-1. 목적

마케터가 디자이너 없이 대시보드에서 홍보 포스터를 만들고 고칩니다. 전문 편집이 필요하면 Figma로 넘겨 이어서 작업합니다.

### 3-2. 흐름

1. 마케터가 **제품명, 홍보 목적, 핵심 문구, 디자인 분위기, 규격**을 입력합니다.
2. AI가 포스터 문구와 배경·제품 연출 이미지를 만듭니다.
3. 제목·본문·배경·제품 이미지 등을 **서로 다른 편집 요소(레이어)**로 구성합니다.
4. 마케터는 대화로 수정을 요청합니다. 예: "제목을 크게", "사진을 오른쪽으로".
5. 결과를 확인하고 PNG/JPG로 내려받습니다.
6. Figma 연동이 검증되면, 편집 가능한 Figma 파일로 이어서 작업합니다.

> **핵심 원칙:** `JPG 생성 → SVG 변환`에 의존하지 않습니다. JPG/PNG는 픽셀이 합쳐진 이미지라서 SVG로 바꿔도 제목·사진·배경이 저절로 나뉘지 않습니다. **처음부터 요소를 나눠서 만들고 관리합니다.** 지금 편집기도 포스터를 요소별 JSON 문서(8장 형식)로 저장합니다.
> 

### 3-3. 기능별 상태

| 기능 | 상태 | 내용 |
| --- | --- | --- |
| 요소(레이어) 구조 | ✅ | 제목·부제·배지·브랜드(글자)·사진·도형·일러스트(이모지 sticker)를 각각 독립 요소로 저장 |
| 규격 | ✅ | 1:1 · **4:5(기본)** · 9:16 · 16:9 중 처음 만들 때 고릅니다. 위치는 % 기준이라 규격을 바꿔도 같은 자리에 남습니다. 초안을 만든 뒤에는 비율 버튼이 꺼집니다(대화로 규격 바꾸기는 📝). |
| 대화로 고치기 | ✅ | `designs.py` `revise_design`(단어 규칙, AI 연결 전). 예: "배경 파랗게", "제목 크게", "제목 'Xin chào'로 바꿔", "명조로", "하트 이모지 추가", "배지 빼줘", "사진 오른쪽으로", "색 조합 바꿔". 바뀌면 새 버전(되돌리기 가능), 못 알아들으면 예시를 안내합니다. |

| 글꼴 | ✅ | 무료 웹글꼴 44종 + 내 PC 글꼴(워드 글꼴 등) (3-5) |
| PNG 내보내기 | ✅ | 규격 원본 크기 (예: 4:5 = 1080×1350) |
| JPG 내보내기 | ✅ | PNG와 같은 그리기 결과를 JPG로 |
| 요청 입력 항목 | 🛠 | 지금은 자유 문장 + 규격만 받습니다. 목적·제품·핵심 문구·분위기를 빠르게 고르는 항목을 첫 화면에 추가합니다. |
| AI 문구·레이아웃 | 📝 | GPT(텍스트 모델)가 문구와 요소 배치를 정해 요소 JSON으로 돌려줍니다. 지금은 정해진 틀로 만듭니다. |
| AI 배경·연출 이미지 | 📝 | 이미지 생성 API로 배경·제품 연출 이미지를 만듭니다. **실제 제품 사진·가격·로고는 원본 자료를 우선** 씁니다. |
| 작업 원본 저장·재편집 | ✅ | 요소 JSON을 버전별로 저장하고, 이전 작업에서 다시 엽니다. |
| SVG 내보내기 | 📝 | 검증 후 단계적으로 추가 (3-6) |
| Figma 연동 | 📝 | 기술 검증 후 결정 (3-4) |

### 3-4. Figma 연동 방식

| 방식 | 구현 방향 | 한계 |
| --- | --- | --- |
| **A. AI 대화형 편집 + Figma 연동 (우선 검증)** | 대시보드의 요청을 AI가 해석하고, 지원되는 Figma 연동 경로(공식 Figma MCP 등)로 레이어를 만들고 고칩니다. | MCP 연동 가능 범위, 인증·권한, 비용, 수정 정확도 검증 필요 |
| B. 자체 편집기 + Figma 연동 | 대시보드에서 글·사진을 직접 눌러 옮기고, 필요할 때 Figma로 넘깁니다. | Figma 호환 내보내기 개발 필요. **자체 편집기는 이미 있으므로** Fabric.js 같은 캔버스 라이브러리는 꼭 필요할 때만 검토 |
| Figma 파일 임베드 | 대시보드에 Figma 파일의 보기·미리보기 표시 | **완전한 Figma 편집기를 대시보드 안에 넣는 것과 다릅니다.** |
- **1차 방향은 A안을 먼저 기술 검증**합니다. 실제 서비스 환경에서 제한되거나 쓰기 불편하면 B안으로 갑니다.
- MCP는 AI와 도구를 잇는 프로토콜입니다. Figma 편집 화면을 대시보드 안에 넣어 주는 기술이 아닙니다.
- Figma 공식 MCP의 지원 범위와 외부 웹 대시보드에서 쓸 수 있는지는 **도입 시점의 공식 문서·인증 방식·계정 권한·요금제**로 확인합니다. 이 문서는 연동 완료나 무제한 편집을 보장하지 않습니다.

### 3-5. 글꼴

| 종류 | 상태 | 내용 |
| --- | --- | --- |
| 무료 웹글꼴 44종 | ✅ | Google Fonts. 고딕 · 명조 · 제목·굵은 · 손글씨·귀여운 · **베트남어·영문**(Be Vietnam Pro·Montserrat 등). 처음 쓸 때만 불러옵니다. |
| 내 PC 글꼴 | ✅ | 글꼴 목록 맨 아래 "내 PC 글꼴 불러오기"를 누르고 권한을 허용하면, 그 PC에 설치된 글꼴(워드 글꼴 포함)을 씁니다. 크롬·엣지만 지원합니다. |
- 내 PC 글꼴은 그 PC에서만 보입니다. PNG로 받으면 그대로 들어갑니다.
- 워드 글꼴 파일을 서버에 올려 나눠 주지 않습니다. 이미지로 만들어 상업적으로 쓸 수 있는지는 글꼴마다 확인합니다.
- 베트남어 문구는 성조를 지원하는 "베트남어·영문" 묶음 글꼴을 권장합니다.

### 3-6. SVG 내보내기 가이드 (📝)

편집할 수 있는 SVG를 만들 때 지킬 것:

- 모든 문구는 아웃라인·패스가 아니라 **`<text>` 요소**로 유지합니다.
- 제목·부제목·본문·CTA를 각각 독립된 글 요소로 둡니다.
- 배경·제품 이미지·장식·글을 별도 그룹(레이어)으로 관리합니다.
- Figma·Illustrator에서 열어 글 수정과 요소 이동이 되는지 실제로 시험합니다.
- 글꼴이 설치되지 않은 곳에서는 글꼴이 바뀌고, 외부 이미지 참조가 빠질 수 있으니 내보내기 전에 검사합니다.
- SVG는 원본 작업 파일을 완전히 대신하지 못합니다. 다시 편집할 수 있도록 요소 JSON도 따로 저장합니다(지금 구조 그대로).

**할 수 없거나 보장할 수 없는 것**

- 포스터 전체를 JPG/PNG 한 장으로 만든 뒤 SVG로 바꿔 **모든 요소를 정확히 되살리기**
- SVG 안의 일반 사진을 모두 편집 가능한 벡터로 만들기
- 어떤 SVG든 Figma/Illustrator에서 원본과 **100% 같게 편집**하기
- Figma MCP만 연결해 **Figma 편집 화면 전체를 대시보드 안에 넣기**

## 4. 카드뉴스 탭 (희주)

인스타그램 게시글로 올릴 카드뉴스를 만듭니다.

### 4-1. 기능별 상태

> 새로 만들기·대화로 고치기가 연결됐습니다(`designs.py` `make_cardnews`·`revise_design`). 첫 화면 "내 카드뉴스" 목록은 아직 시연 카드만 보입니다.

| 기능 | 상태 | 내용 |
| --- | --- | --- |
| 임시 템플릿 4종 | ✅ | 깔끔 정보형 · 사진 강조형 · 체크리스트형 · 감성 문구형. **받을 실제 템플릿으로 바꿀 예정**입니다. |
| 템플릿 바꾸기 | ✅ | 만들 때·작업 중 모두 말로 고릅니다: "체크리스트형으로 (바꿔줘)". 글·색·사진은 유지됩니다. 첫 화면·위쪽 목록에서 고르는 버튼은 📝 |
| 구성 | ✅ | 3~6장(기본 5장). 1장은 표지, 나머지는 안쪽 장(쪽 번호·제목·본문) |
| 규격 | ✅ | **4:5(기본)·1:1**만 (다른 비율 버튼은 숨김, 초안 뒤에는 꺼짐) |
| 고치기·내보내기 | ✅ | 포스터 편집기(`sns_editor.js`)를 함께 씁니다. 장 번호 버튼으로 장을 옮기고, 이 장 PNG/JPG 또는 모든 장 PNG로 받습니다. 대화로 고치기는 "2장 배경 금색"처럼 장을 말하면 그 장을, 말하지 않으면 1장을 고칩니다(보고 있는 장 기준은 편집기 `currentPage()` 추가 후). |
| 실제 템플릿 | 📝 | 마케터가 템플릿 몇 개를 줍니다(4-2). |
| 기본 프롬프트 | 📝 | 모든 카드뉴스 생성에 항상 깔리는 기본 지침을 설정합니다(4-3). |
| 생성 방식 | 📝 | GPT 또는 Canva 중 정합니다(4-4). |

### 4-2. 템플릿 (📝)

- 마케터가 실제로 쓸 카드뉴스 템플릿을 몇 개 줍니다.
- 받은 템플릿은 다음 중 맞는 방식으로 등록합니다.
    - **우리 편집기 템플릿:** 요소 JSON(배치·글꼴·색)으로 옮겨 지금의 템플릿 4종을 대신합니다.
    - **Canva 브랜드 템플릿:** Canva에 올려 두고, 우리 글·사진을 채워 넣습니다.
- "학습"은 AI 모델을 새로 훈련하는 것이 아닙니다. **템플릿과 좋은 예시를 참고 자료로 AI 요청에 함께 넣어** 그 스타일을 따르게 하는 방식입니다.

### 4-3. 기본 프롬프트 (📝)

카드뉴스를 만들 때마다 **항상 먼저 들어가는 기본 지침**입니다. 마케터는 매번 같은 조건을 말하지 않아도 됩니다.

들어갈 내용 (예시, 실제 문구는 마케터가 정합니다):

- 베트남에서 **금기시하는 표현·색·상징**을 쓰지 않는다.
- 베트남 현지 **최신 유행**을 따른다.
- **성차별·인종차별** 등 차별적인 표현을 쓰지 않는다.
- **한국 브랜드(한정선)다운 색과 느낌**을 살린다.
- (그 밖에 브랜드 톤, 광고 표현 주의사항 등)

| 항목 | 설계 |
| --- | --- |
| 저장 위치 | 설정 파일(예: `content_studio/prompts/cardnews_base.md`) 또는 화면에서 고치는 설정 — 9장에서 결정 |
| 쓰는 곳 | 카드뉴스 생성·수정 요청을 AI(GPT·Canva)에 보낼 때 맨 앞에 붙입니다. |
| 사용자 요청과의 관계 | 기본 프롬프트 + 템플릿 참고 + 사용자 요청 순서로 보냅니다. 사용자 요청이 기본 지침과 충돌하면 기본 지침을 따릅니다. |
| 광고 표현 검수와의 관계 | 기본 프롬프트로 예방하고, 결과 문구는 광고 표현 검수(6장)로 한 번 더 확인합니다. |

### 4-4. 생성 방식 (📝)

| 방식 | 내용 | 확인할 것 |
| --- | --- | --- |
| GPT | 기본 프롬프트 + 템플릿 참고로 장별 문구·배치(요소 JSON)를 만들고, 우리 편집기에서 고칩니다. | 모델·비용, 결과 형식 안정성 |
| Canva | Canva Connect API로 브랜드 템플릿에 글·사진을 채우거나 디자인을 만들고 내보냅니다. | 계정 등급별 API 범위(자동 채우기·브랜드 템플릿은 상위 등급 필요 가능), OAuth 앱 등록 |

## 5. 배경 제거 (희주)

제품 사진의 배경을 지우고 투명 배경 PNG로 받는 기능입니다. 포스터·숏폼·카드뉴스에 들어갈 **한정선 찹쌀떡 누끼 이미지**를 빠르게 만드는 것이 목적입니다.

### 5-1. 위치와 흐름 (✅)

별도 페이지를 두지 않고, **화면 위쪽 [✂️ 배경 제거] 버튼**에서 엽니다. 세 탭(포스터·카드뉴스·영상)의 첫 화면·작업 화면 어디서든 보입니다.

1. 위쪽 **[✂️ 배경 제거]** 버튼을 누르면 팝업이 열립니다.
2. 팝업에서 내 사진을 고릅니다.
3. **배경 제거**를 누르면, 처리하는 동안 로딩 표시를 보여줍니다. (처음 한 번은 모델 내려받기 때문에 더 오래 걸립니다)
4. 결과는 체크무늬(투명) 배경 위에 보여줍니다.
5. **PNG 받기**로 투명 PNG를 받습니다.

- 버튼은 템플릿(`content_studio_index.html`, 유진)에 `data-role="remove-bg"`로 있고, 동작은 `sns_image.js`(희주)가 그 버튼을 찾아 붙입니다. `sns.js`는 관여하지 않습니다.
- 자르기·회전·보정이 있는 사진 편집 창은 📝입니다.

### 5-2. 입력 조건 (✅)

| 항목 | 기준 |
| --- | --- |
| 형식 | JPEG, PNG, WEBP |
| 용량 | 제한 없음 (큰 사진은 처리 시간이 길어질 수 있음) |
| 크기 | 가로·세로 각각 최대 4096px |
| 개수 | 한 번에 1장 |
- 같은 조건을 **화면(JS)과 서버(Python) 양쪽**에서 검사합니다. 화면 검사는 편의용이고, 최종 판단은 서버가 합니다.
- 서버는 확장자만 보지 않고 Pillow로 실제 이미지를 열어 형식과 크기를 확인합니다.

### 5-3. 구현 방식 — rembg (무료·로컬 실행, API 키 없음) (✅)

외부 API를 쓰지 않고, 서버 PC에서 **rembg** 라이브러리의 **`birefnet-general`** 모델로 배경을 지웁니다. 무료이고 API 키가 필요 없습니다.

> `routes_media.py`에 구현됐습니다. 각자 `pip install -r requirements.txt`로 rembg를 설치해야 동작합니다(없으면 "아직 설치되지 않았습니다" 안내). 예전 설계(OpenCV GrabCut 직접 구현)와 remove.bg 연동은 쓰지 않습니다.

| 구분 | 선택 | 사용 목적 |
| --- | --- | --- |
| 배경 분리 | `rembg` (`birefnet-general` 모델) | 제품과 배경을 나눈 투명 마스크 |
| 이미지 입출력 | `Pillow` | 형식·크기 검사, 투명 PNG 저장 |

- **처음 실행할 때 모델 파일 약 1GB를 내려받습니다.** 그다음부터는 서버 PC에 저장된 모델을 씁니다.
- 사진 1장에 **1~2분** 걸릴 수 있습니다. 처리 중에는 로딩 표시를 보여줍니다.
- **가장자리 다듬기**(alpha matting)를 켜고 끌 수 있습니다. 켜면 머리카락·가루처럼 얇은 경계가 자연스러워지는 대신 더 오래 걸립니다.
- 라이브러리 추가는 PM1 상준에게 요청했습니다(8장).

```
원본 이미지
   ↓ ① 형식·크기 검사 (Pillow로 실제 이미지 열기)
   ↓ ② rembg + birefnet-general로 제품 마스크 계산
   ↓ ③ (선택) 가장자리 다듬기 (alpha matting)
   ↓ ④ 마스크를 알파 채널로 붙여 PNG 저장
결과 PNG (배경 투명)
```

### 5-4. 한계와 대응

AI 모델이라 배경이 복잡해도 대체로 잘 되지만, 아래 경우는 결과를 꼭 확인합니다.

| 잘 되는 사진 | 확인이 필요한 사진 |
| --- | --- |
| 제품이 또렷하고 사진 안에 다 들어온 사진 | 제품이 사진 가장자리에서 잘린 사진 |
| 제품과 배경 색이 다른 사진 | 흰 찹쌀떡 + 흰 배경처럼 색이 비슷한 사진 |
| 제품 하나만 있는 사진 | 접시·손·포장 등 여러 물체가 겹친 사진 (무엇을 남길지 모델이 정함) |
- 팝업에 "제품이 또렷하게 다 보이는 사진일수록 결과가 깔끔합니다."를 표시합니다.
- 경계가 거칠면 **가장자리 다듬기**를 켜고 다시 처리합니다.
- 큰 사진이나 첫 실행은 오래 걸리므로, 시연 전에 서버 PC에서 한 번 실행해 모델을 미리 내려받아 둡니다.
- 흰 찹쌀떡 사진은 시연 전에 실제 사진으로 미리 시험합니다.

### 5-5. API (✅)

**`POST /content_studio/media/api/remove-bg`**

- 요청: `multipart/form-data`, 필드 `image`, 선택 필드 `alpha_matting`(가장자리 다듬기, 기본 끔)
- 다듬기만 바꿔 다시 처리할 때는 `image` 대신 처음 응답의 `file_id`와 `alpha_matting`을 보냅니다.
- 처리에 1~2분 걸릴 수 있어, 화면은 응답을 기다리는 동안 로딩 표시를 유지합니다.

```json
{ "ok": true, "file_id": "<파일ID>", "result_url": "/content_studio/media/remove-bg/result/<파일ID>.png", "width": 1200, "height": 1200 }
```

```json
{ "ok": false, "error": "JPEG·PNG·WEBP 이미지만 올릴 수 있습니다." }
```

**`GET /content_studio/media/remove-bg/result/<파일ID>.png`**: 결과 PNG를 내려받습니다.

> 위 형식으로 `routes_media.py`와 팝업(`sns_image.js`)에 구현돼 있습니다.
> 

### 5-6. 저장과 상태

| 구분 | 위치 |
| --- | --- |
| 원본 | `instance/uploads/content_studio/` |
| 결과 | `instance/exports/content_studio/` |
- 파일 이름은 사용자가 올린 이름을 쓰지 않고 서버가 만든 ID(`uuid`)로 저장합니다.
- 1차 버전은 DB에 기록하지 않습니다.

| 상태 | 화면 표시 |
| --- | --- |
| 처리 전 | 사진 고르기, "배경 제거" 버튼, 안내 문구 |
| 처리 중 | 걸린 초를 세는 로딩 표시, 버튼 누를 수 없음 |
| 완료 | 체크무늬 위 결과, "PNG 받기" |
| 형식·크기 오류 | 빨간 안내 문구, 서버로 보내지 않음 |
| 처리 실패 | "배경을 제거하지 못했습니다. 다른 사진으로 다시 시도해 주세요." |
- **범위에서 제외 (추후 검토):** URL로 이미지 불러오기(외부 접속 보안 검토 필요), 여러 장 한 번에 처리, 배경색·배경 이미지 교체, 제품 영역 직접 지정, 지우개·복원 브러시, 처리 결과를 바로 포스터 사진으로 쓰기

## 6. 영상 탭 (유진)

흐름: **① 초안 → ② 사용자 검토·승인 → ③ 생성.** ③은 서버 PC에 로그인된 Higgsfield CLI(유진 Ultra 계정)로 연결했습니다. **실제 생성 시험은 아직 하지 않았습니다**(가짜 CLI 테스트만 통과).

| 단계 | 상태 | 내용 |
| --- | --- | --- |
| ① 초안 | ✅ | 요청을 읽어 장면 구성과 카메라·조명·분위기·배경을 정리합니다. 컷 수는 길이로 정합니다(5초 3컷, 10초 4컷 … 30초 8컷). 제품을 안 말하면 먼저 되묻습니다. |
| 분위기 8가지 | ✅ | **프리미엄 광고(기본) · 따뜻한 감성 · 브이로그·리뷰 · 역동적 숏폼 · 레트로 · 판타지 변신 · 미니어처 월드 · ASMR 클로즈업.** 요청 단어로 고르고(기념일 영상은 따뜻한 감성), 분위기마다 콘셉트 제목·편집 리듬·구간 이름·컷 길이 비율·카메라·조명·소리·금지 문구가 달라집니다. "브이로그 느낌으로", "고급스럽게", "미니어처로", "판타지로", "ASMR로"처럼 말로 바꿉니다. 판타지·미니어처는 장면이 화려해 제품 모양이 흐트러지기 쉬우므로 미리보기 이미지를 먼저 만들어 첫 장면으로 쓰는 것을 권합니다. |
| 장면 구성 | ✅ | 컷마다 시간·장면·베트남어 자막. 시간을 눌러 끝나는 초를 고치고, ×로 컷 삭제(앞 컷이 시간을 이어받음), [+ 컷 추가]로 마지막 컷 앞에 추가(최대 = 길이 초, 12컷). 말로도 됩니다: "3번 장면 빼줘", "컷 하나 추가". |
| 자막 | ✅ | 영상에는 글자를 그리지 않고, 베트남어 자막을 장면마다 따로 저장해 위에 얹습니다. 2번 자막 "…", "2번 자막 지워", "자막 빼줘". 문구는 원어민 검수 전 시연입니다. |
| ② 프롬프트 검토 | ✅ | Higgsfield로 보낼 **영어 프롬프트**를 예시 프롬프트 분석으로 정한 순서로 만듭니다: 콘셉트 제목·브랜드·길이·비율·화질 → 스타일 → 편집 리듬 → 제품 겉모습 → 배경·분위기 → 구간별 컷 → 카메라 → 조명·색감 → 연속성 → 소리 → 금지. 컷은 **소개 → 디테일 → 클라이맥스(끝에서 두 번째) → 히어로** 자리로 나누고, 컷마다 구간 이름·카메라·장면·움직임(물리·공기 중 가루 등)·효과음(ASMR)을 적습니다. 디테일 컷에는 찹쌀떡 질감 단어(쫀득하게 늘어남, 흩날리는 쌀가루, 말랑하게 눌림, 단면 속 소, 촉촉한 광택)를 차례로 씁니다. 연속성 줄은 "갑자기 나타나거나 모양이 변하지 않게"를, 사진이 있으면 "마지막 히어로 컷은 사진과 정확히 일치"를 넣고, 금지 줄에는 CGI 느낌·가짜 물리·과한 채도를 넣습니다. 영어가 **2,500자**(Kling 쪽 문서의 흔한 한도, Higgsfield 실제 한도는 확인 전)를 넘으면 디테일 컷의 구간 이름·질감 문장·효과음을 빼고 금지 줄을 짧게 씁니다. **영어는 읽기 전용**이고 오른쪽 위 [복사]로 복사합니다. **고치는 것은 옆의 한국어 칸**입니다: 저장하면 자동 한국어와 줄마다 비교해 바뀌지 않은 줄은 그대로, 지운 줄은 영어에서도 빼고, 고친 줄은 아는 표현(카메라·조명·분위기·배경·장면·분위기 5종 문구 등)만 영어로 바꿉니다. 모르는 표현이 남은 줄은 영어를 바꾸지 않고 "영어에 반영하지 못한 줄"로 보여 줍니다(영상 모델에 한국어를 보내지 않음). AI를 연결하면 이 부분을 번역으로 바꿉니다(10장). 입력줄로 고치면 자동 프롬프트를 새로 만들고 직접 고친 한국어는 지웁니다. 바뀌면 다시 검토가 필요합니다. |
| 말로 고치기 | ✅ | "더 밝게 / 카메라 천천히 / 한입 먹는 장면 / 15초로 / 소리 켜줘 / 세로로" (단어 규칙, AI 연결 전) |
| 규격 | ✅ | 9:16 · 16:9 · 1:1, **5~30초**(1초 단위), 소리 켬/끔 |
| 미리보기 이미지 | ✅ | [미리보기 이미지 만들기]로 첫 장면 그림을 먼저 만듭니다(Nano Banana 2, 1.5 크레딧). 완료되면 미리보기 자리에 보이고, 영상은 이 그림을 첫 장면으로 만듭니다(image-to-video). |
| ③ 생성 | ✅ | **Kling 4.0 · 720p.** 버튼을 누르면 먼저 확인 창에 **이번에 쓰일 크레딧 · 계정 남은 크레딧 · 오늘 대시보드 사용량 / 200**을 보여 주고, [실행]을 눌러야만 요청합니다. 대기 중 → 만드는 중 → 완료(재생) / 실패 / 거절됨. 만드는 동안 8초마다 상태만 확인합니다(다시 만들지 않음). 완료되면 남은 크레딧을 다시 보여 줍니다. 저장하지 않은 수정이 있으면 버튼이 꺼집니다. |
| 하루 한도 | ✅ | **대시보드에서 쓴 크레딧만** 한국 시간 0시 기준으로 하루 200까지. 넘으면 실행을 막습니다. 남은 크레딧은 **계정 전체** 기준(웹에서 쓴 것 포함)으로 Higgsfield에서 바로 받아 옵니다. |
| 로그인이 풀렸을 때 | ✅ | CLI가 없거나 로그인이 풀리면 "로그인 필요" 안내만 보여 주고 요청은 보내지 않습니다. |

Higgsfield 연동 (`higgsfield.py`, CLI 방식)

- **API 키를 쓰지 않습니다.** Ultra 구독 크레딧은 API 지갑과 따로라서, 서버 PC에 설치한 Higgsfield CLI(`@higgsfield/cli`)에 유진 계정으로 로그인해 그 크레딧을 씁니다.
- 처음 한 번: Node.js 설치 → `npm install -g @higgsfield/cli` → `higgsfield auth login`(브라우저 승인) → `higgsfield workspace set <Private 워크스페이스 ID>`. 로그인은 가끔 풀리므로 그때 다시 `higgsfield auth login`.
- **로그인한 PC에서 켠 대시보드에서만** 생성됩니다. 누가 눌러도 유진 계정 크레딧이 나갑니다.
- 크레딧이 나가는 것은 `generate create`(=`POST /api/chats/<id>/generate`) 하나뿐입니다. 비용(`generate cost`)·잔액(`account status`)·상태(`generate get`) 확인은 무료입니다.
- 화면에서 확인한 비용과 서버가 다시 잰 비용이 다르면 요청하지 않고 새 숫자로 다시 묻습니다.
- 결과가 늦으면 다시 만들지 않고 상태만 확인합니다(이중 결제 방지). 실패한 작업도 하루 사용량에서 빼지 않습니다(환불 여부를 알 수 없어 넉넉하게 셈).
- 제품 사진은 CLI가 직접 올리므로 `PUBLIC_BASE_URL`이 필요 없습니다. (사진 첨부 연결은 아직 📝)
- Kling 4.0에는 소리 켬/끔 옵션이 없어, 소리는 프롬프트 문장으로만 전달됩니다.
- 약관(higgsfield.ai 이용약관): CLI는 "본인·회사 내부 업무" 목적으로 허용, 활동은 모두 계정 주인 책임(11.12), **계정 공유 금지(2.4)**. 팀 전체에 열기 전에 PM1 상준과 정합니다(10장).
- 예상 크레딧(2026-10-24 `generate cost`): 영상 720p 5초 7.5 · 15초 22.5 · 30초 45, 미리보기 이미지 1.5.

### 광고 표현 검수·숏폼 콘티 (희주, 📝)

- **광고 표현 검수:** 최상급·효능·할인 등 주의 표현을 표시하고, 이유·바꿔 쓰기·KOTRA 자료 링크를 보여줍니다. **"참고 안내이며 법적 판단이 아님"**을 항상 표시합니다.
- **숏폼 콘티:** 대화에서 "숏폼 콘티 짜줘"라고 하면 장면별 화면과 자막을 만듭니다.

| **5. 템플릿·프롬프트** | 영상 프롬프트 규칙 다듬기 | 받은 카드뉴스 템플릿 등록, **카드뉴스 기본 프롬프트** 반영 |
| **6. 마무리** | 생성 실패·거절 처리, 결과 영상 저장 | SVG·Figma 내보내기(검증 후), 상태 처리 점검 |

### 브랜치와 머지

- 유진·희주는 **각자 개인 브랜치**에서 작업하고 `premain`으로 PR을 올립니다.
- 희주의 PR은 PM2 유진이, 유진의 PR은 PM1 상준이 머지합니다.

### 화면·코드 충돌 방지

- CSS는 `.studio-chat`, `.studio-tabs`, 사진 편집 창은 `.img-editor` 아래에서만 씁니다.
- JS는 ES 모듈입니다. 전역 변수·함수를 만들지 않습니다.
    - `sns.js`가 `sns_editor.js`·`sns_video.js`·`sns_image.js`를 import합니다.
    - `sns_editor.js`가 `sns_fonts.js`를 import합니다.
- 이미지는 `static/images/sns/`에만 넣습니다.

## 11. 완료 기준

**공통**

- [ ]  각자 ✏️ 표시된 파일만 수정했다.
- [ ]  세 탭 모두 첫 화면(내 작업 가로 목록·추천) → 작업 화면 → 이어서 하기가 동작한다.
- [ ]  되돌리기·다시하기가 대화 수정과 직접 수정 모두에 동작한다.
- [ ]  시연 결과와 실제 생성 결과를 화면에서 구분한다.
- [ ]  업로드 사진·생성 결과·API 키가 커밋에 포함되지 않았다.

**포스터**

- [ ]  제목·본문·사진·배경이 독립 요소로 만들어지고, 대화와 직접 수정으로 각각 고칠 수 있다.
- [ ]  PNG/JPG로 받을 수 있고, 작업 원본(요소 JSON)을 다시 열어 고칠 수 있다.
- [ ]  Figma 연동 방식(A/B)의 기술 검증 결과를 기록했다.

**카드뉴스**

- [ ]  받은 템플릿으로 카드뉴스를 만들 수 있다.
- [ ]  기본 프롬프트가 모든 생성 요청에 들어간다.

**배경 제거**

- [ ]  JPEG·PNG·WEBP 각각 배경이 지워지고 투명 PNG로 받아진다.
- [ ]  4096px 초과, 지원하지 않는 형식이 화면과 서버 양쪽에서 막힌다. (용량 제한 없음)
- [ ]  흰 배경·유색 배경 제품 사진에서 제품 테두리가 깔끔하게 남는다.
- [ ]  가장자리 다듬기를 켜면 같은 원본으로 다시 처리된다.
- [ ]  처음 실행 때 모델을 내려받고, 그다음부터 사진 1장이 1~2분 안에 처리된다.
- [ ]  처리 중에는 버튼을 다시 누를 수 없고, 실패해도 화면이 멈추지 않고 안내 문구가 나온다.

**영상**

- [ ]  사용자가 프롬프트를 승인하기 전에는 생성 요청을 보내지 않는다.
- [ ]  실행 전 확인 창에 이번 크레딧 · 계정 남은 크레딧 · 오늘 사용량이 나오고, [실행]을 눌러야만 요청한다.
- [ ]  하루 200(대시보드 사용분)을 넘으면 요청하지 않는다.
- [ ]  실제 생성 1회로 미리보기 이미지 → 영상 완료 · 재생을 확인했다.

**검수**

- [ ]  광고 표현 검수에 "참고 안내이며 법적 판단이 아님"이 표시된다.
