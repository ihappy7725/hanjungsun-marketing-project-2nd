# MARKET_ANALYSIS 구현·데이터·API 통합 문서

> 작성 기준일: 2026-10-27  
> 대상 경로: `market_analysis/`  
> 대상 독자: 개발자, 데이터 담당자, 한정선 글로벌 마케팅 담당자  
> 목적: 현지 시장 분석 기능에서 무엇을 만들었고, 어떤 데이터를 어떻게 수집·정제·표시했는지 설명하기 위한 인수인계 문서

## 1. 한 문장 요약

`MARKET_ANALYSIS`는 베트남 시장의 검색 트렌드, 경쟁제품, 국가·문화, 광고 사례를 출처가 있는 데이터로 정리한 뒤, 사용자가 선택한 목표·기간·채널에 맞춰 OpenAI가 근거 기반 실행안을 작성하도록 만든 Flask 대시보드입니다.

핵심 원칙은 다음과 같습니다.

1. 화면 접속 때마다 외부 사이트를 크롤링하지 않음
2. 수집 스크립트가 외부 데이터를 원본 그대로 보관함
3. 서비스 코드가 누락값·비교 기준·순위·증감률을 정제함
4. 화면은 정제된 JSON·CSV만 읽음
5. AI에는 확인된 근거만 전달하고, 생성 결과도 다시 검증함
6. API 키와 비밀값은 브라우저에 전달하지 않음
7. 판매가 확인되지 않은 후보와 비식품 검색 결과는 확정 경쟁제품에서 제외함

## 2. 최종 화면 구성

화면 주소는 `/market_analysis/`이며 국가 선택과 다음 네 개의 탭으로 구성됩니다.

### 2.1 국가·문화

- 베트남 기본 정보: 인구, 1인당 GDP, 도시화율
- 베트남 디저트 소비 문화
- 광고에서 피하거나 검토해야 할 표현
- 선호 색상과 색상의 의미
- 상징물과 사용 주의사항
- 현지 소비자가 선호하는 패키징 방식
- 각 정보의 출처와 확인일

공휴일·기념일은 국가·문화 화면의 핵심 카드가 아니라 AI 실행 일정의 근거로 사용합니다.

### 2.2 트렌드 분석

- 카테고리별 인기 메뉴 순위
- 카테고리 관심도와 최근 52주 흐름
- 월별 검색 계절성
- 과일 맛 검색 관심도
- 베트남 지역별 관심도
- 베트남 광고에서 반복되는 트렌드

트렌드 카테고리는 다음 네 가지입니다.

| 화면 카테고리 | 대표 검색 기준 | 목적 |
|---|---|---|
| 떡·모찌 | `bánh mochi`, `bánh dày` | 직접 경쟁 시장 관심도 파악 |
| 현지 찹쌀 디저트 | `bánh nếp` | 현지 찹쌀 식감 대체재 파악 |
| 현지 과일 디저트 | 과일 우유·차·케이크·사탕·건과일·아이스크림 검색 묶음 | 현지 과일 디저트 수요 파악 |
| 한국 디저트 | `bánh hàn quốc` 및 연관 검색 결과 | 한국 디저트 관심과 메뉴 후보 파악 |

### 2.3 경쟁사 분석

- `전체 목록`: 검색, 유형 필터, 원산지 필터, 판매가 정렬, 페이지 이동
- 제품 상세: 브랜드, 상품명, 경쟁 유형, 구성, 판매가, 판매처별 가격, 상품 페이지 링크
- `마케팅`: 선물·포장, 명절·시즌, 가격·묶음 혜택, 채널 확보, 원재료·트렌드형 제품의 실제 사례
- `주요 경쟁자`: 마케터가 먼저 비교해야 할 여섯 개 경쟁군

현재 주요 경쟁자는 자동 판매순위가 아닙니다. 판매 확인, 유통 범위, 제품 형태, 가격 비교 가치, 현지성 등을 근거로 수동 선정한 우선 검토 목록입니다.

### 2.4 AI 인사이트

사용자가 최소한으로 입력하는 항목은 다음과 같습니다.

- 이번 목표
- 실행 기간
- 주력 채널
- 선택 과일
- 예산 범위(선택)
- 추가 메모(선택)

서버는 트렌드, 경쟁제품, 문화 가이드, 공휴일·기념일, 의사결정 카드를 근거 묶음으로 만든 후 OpenAI에 전달합니다. 생성 결과에는 결론, SWOT, 실행 일정, 채널 제안, 근거 태그, 데이터 한계가 포함됩니다.

## 3. 전체 데이터 흐름

```text
검색어·카테고리 설정
        ↓
SerpApi Google Trends / 공개 상품 페이지 / 수동 광고 조사 / 공공 API
        ↓
원본 JSON·CSV 보관
        ↓
검증·중복 제거·누락값 처리·가격 및 관심도 계산
        ↓
화면용 JSON·CSV 생성
        ↓
Flask 내부 API
        ↓
국가·문화 / 트렌드 / 경쟁사 / AI 인사이트 화면
        ↓
검증된 근거만 OpenAI에 전달 → 결과 후처리 및 근거 검사
```

페이지 접속은 외부 API 호출을 발생시키지 않는 것이 기본입니다. 단, 사용자가 실제 AI 인사이트 생성을 요청하면 OpenAI API와 공휴일 API를 호출할 수 있습니다.

## 5. 외부 API와 활용 방식

### 5.1 SerpApi Google Trends

환경변수: `SERPAPI_API_KEY`

호출 주소:

```text
https://serpapi.com/search.json
```

기본 파라미터:

| 파라미터 | 값 또는 용도 |
|---|---|
| `engine` | `google_trends` |
| `data_type` | 조회할 Google Trends 구성 |
| `q` | 베트남어 검색어 또는 비교 검색어 묶음 |
| `geo` | 기본 `VN`, 한국인 다낭 여행은 `KR` |
| `hl` | 기본 `vi`, 한국 검색은 `ko` |
| `tz` | 베트남 `-420`, 한국 `-540` |
| `date` | 최근 비교 기간 또는 최근 5년 |

사용한 `data_type`은 다음과 같습니다.

| 이름 | 가져오는 데이터 | 화면 활용 |
|---|---|---|
| `TIMESERIES` | 시간에 따른 상대 관심도 | 카테고리 흐름, 과일 관심도, 계절성, 증감률 |
| `RELATED_QUERIES` | 인기·급상승 연관 검색어 | 카테고리별 메뉴 후보와 검색 순위 |
| `RELATED_TOPICS` | 관련 주제와 유형 | 식품 관련 후보의 의미 확인 |
| `GEO_MAP_0` | 지역별 상대 관심도 | 베트남 지역별 관심도 |

SerpApi는 한 번의 `TIMESERIES` 비교에서 최대 다섯 검색어만 사용하도록 코드에서 제한합니다. 여섯 개 이상이면 첫 검색어를 공통 기준 검색어로 두고 `[기준 + 후보 4개]` 단위로 나눈 뒤 기준 검색어 평균값으로 스케일을 맞춥니다.

API 응답에서 `api_key`와 SerpApi의 직접 JSON 주소는 원본 저장 전 제거합니다. 비밀키가 파일이나 브라우저 응답에 남지 않도록 하기 위한 처리입니다.

### 5.2 OpenAI API

환경변수: `OPENAI_API_KEY`

현재 구현:

- 엔드포인트: `https://api.openai.com/v1/chat/completions`
- 모델: `gpt-4o-mini`
- 응답 형식: JSON object
- temperature: `0.3`
- 제한 시간: 60초

OpenAI에 원본 파일 전체를 보내지 않습니다. 서버가 다음 정보를 근거 문장으로 축약한 뒤 전달합니다.

- 트렌드 수치와 확인일
- 과일 관심도 및 피크 월
- 확정 경쟁제품과 가격·판매처 근거
- 국가·문화 및 광고 주의 근거
- 공휴일과 실행 리드타임
- 서버가 계산한 맛·가격·채널 카드

AI 결과를 바로 화면에 표시하지 않고 다음 검사를 수행합니다.

- 존재하지 않는 근거 태그 제거
- 근거에 없는 숫자 제거
- 서버가 고른 과일 후보와 기간 범위 확인
- 필수 JSON 구조 확인
- 근거 부족 문장 제외 건수 기록
- 데이터가 없으면 한계 문구 추가

### 5.3 공휴일 API

사용 위치: AI 실행 일정

1차 공개 API:

```text
https://date.nager.at/api/v3/PublicHolidays/{year}/VN
```

보조 API:

```text
https://calendarific.com/api/v2/holidays
```

Calendarific은 `CALENDARIFIC_API_KEY`가 있을 때 사용합니다. 외부 API 실패에 대비하여 코드 안의 베트남 핵심 마케팅 캘린더를 함께 사용하고, 결과는 메모리 캐시합니다.

### 5.4 World Bank Indicators API

키가 필요하지 않은 World Bank API로 국가 기본 정보를 조사했습니다.

| 지표 | 코드 |
|---|---|
| 인구 | `SP.POP.TOTL` |
| 1인당 GDP | `NY.GDP.PCAP.CD` |
| 도시화율 | `SP.URB.TOTL.IN.ZS` |

확인된 값과 연도, 지표 코드, 원문 URL을 `data/country_vn.json`에 저장했습니다. 현재 화면은 이 파일을 읽으며 페이지 접속 때 World Bank를 다시 호출하지 않습니다.

### 5.5 경쟁제품 후보 발굴용 SerpApi Google Search

`build_competitor_research.py --serpapi` 실행 시 Google 색인 검색으로 Shopee·Lazada·TikTok Shop 후보 링크를 찾습니다.

이 단계의 검색 결과는 경쟁제품 확정이 아닙니다. 후보 링크를 실제 공개 상품 페이지에서 다시 확인하고, 판매 상태·가격·상품 유형을 확인할 수 있을 때만 확정 목록에 포함합니다. 검색 1개당 SerpApi 호출 1회가 차감되므로 `--serpapi-limit`으로 최대 호출 수를 제한합니다.

### 5.6 광고 조사 출처

광고 트렌드는 한 개 API가 자동으로 만든 결과가 아닙니다. 다음 공개 자료를 직접 확인하여 정리했습니다.

| 출처 | 표본 | 사용 정보 |
|---|---:|---|
| TikTok Creative Center | 광고 12건 | 광고 ID, 업종, 목표, 성과 구간, 영상 표현 |
| Meta 광고 라이브러리 | 활성 광고 12건 | 라이브러리 ID, 광고주, 시작일, 문구, CTA |
| YouTube Shorts | 검색 결과 10건 | 제목, 표시 조회수, 콘텐츠 주제. 광고 성과로는 사용하지 않음 |
| Shopee Vietnam | 고유 상품 10건 | 상품명, 가격, 할인, 중량·수량, 평점, 판매 지역 |
| Google Trends | 검색어 4개 | 최근 90일 상대 관심도와 연관 검색 신호 |

Lazada와 TikTok Shop에서 직접 검증 가능한 최신 목록을 확보하지 못한 항목은 0건으로 명시하고 결론 근거에서 제외했습니다.

`AdTrendCollector`는 자동 크롤러가 아니라 담당자가 만든 공개 광고 사례 파일을 읽는 검증기입니다. 필수 필드 확인, 날짜 형식 확인, URL 중복 제거, 거부 사유 기록을 수행합니다.

## 6. 트렌드 데이터 수집과 정제

### 6.1 검색어 설정

`config/trend_keywords_vn.json`에서 다음을 관리합니다.

- 카테고리 이름과 대표 검색어
- 상품 순위의 출발 검색어와 포함·제외 단어
- 후보 검색어
- 과일 맛 10종
- 계절성 주제
- 베트남어→한국어 표시명
- 베트남 행정 지역 코드→한국어 지역명
- 섹션별 수집 중단 여부

여러 검색어를 하나의 카테고리로 볼 때는 Google Trends의 `+` 연산으로 결합합니다. 단, 결합 검색어의 관심도는 개별 검색어의 절대 검색량 합계가 아니라 Google Trends가 산출한 상대 지수입니다.

### 6.2 수집 실행

```powershell
python market_analysis/collect_trends.py --plan
python market_analysis/collect_trends.py
python market_analysis/collect_trends.py --all
python market_analysis/collect_trends.py --sections categories rankings
```

- `--plan`: 실제 호출 없이 대상과 예상 호출 수 확인
- 기본 실행: 권장 갱신 주기가 지난 영역만 수집
- `--all`: 일시 정지 영역을 제외하고 전체 수집
- `--sections`: 필요한 영역만 선택 수집

권장 주기는 다음과 같습니다.

| 영역 | 갱신 주기 |
|---|---|
| 카테고리, 순위, 과일 관심도 | 3.5일 |
| 지역, 연관 검색어, 광고 | 7일 |
| 계절성 | 30일 |

수집에 실패한 영역은 이전 정상 데이터를 유지하고 오류 시간과 메시지만 갱신합니다. 한 카테고리의 순위 수집이 실패해도 다른 카테고리는 갱신할 수 있습니다.

### 6.3 원본 보관

모든 SerpApi 응답은 계산 전에 `data/raw/`에 날짜·시간이 포함된 JSON으로 저장합니다. 따라서 화면 수치가 어떻게 만들어졌는지 원본까지 역추적할 수 있습니다.

최신 정제 결과는 `data/trends_vn.json`에 저장합니다. 저장할 때 임시 파일을 만든 뒤 `os.replace`로 교체하여 중간에 프로세스가 종료되어도 JSON이 반만 쓰이는 문제를 줄였습니다.

### 6.4 시계열 누락값 처리

다음 값은 임의로 0으로 만들지 않습니다.

- API 응답에 없는 날짜
- 아직 집계 중인 `partial_data` 마지막 주
- 여러 비교 검색어가 같은 날짜에 모두 0인 수집 공백

누락값을 0으로 채우면 실제 관심 하락처럼 보일 수 있기 때문입니다.

### 6.5 관심도와 증감률

기본 지표는 다음과 같습니다.

```text
최근 관심도 = 최근 12주 관심도 평균

전년 동기 증감률 =
(최근 12주 평균 - 52주 전 같은 기간 12주 평균)
÷ 52주 전 같은 기간 12주 평균 × 100

단기 증감률 =
(최근 4주 평균 - 직전 4주 평균)
÷ 직전 4주 평균 × 100
```

전월 대비가 아니라 전년 동기를 기본으로 사용하는 이유는 명절·과일·관광 수요의 계절 효과를 줄이기 위함입니다.

데이터 커버리지가 70% 미만이거나 최근 평균이 없으면 `insufficient`로 표시합니다. 전년 값이 0이고 최근 관심도가 5 이상이면 무한대 증감률 대신 `신규 관심`으로 분류합니다.

### 6.6 순위 규칙

- 인기순: 최근 12주 평균 관심도가 높은 순서
- 성장순: 전년 동기 증감률이 높은 순서
- 관심도 5 미만: 순위 제외
- 급상승 표시: 전년 동기 대비 50% 이상
- 연관 검색어 기반 순위: Google의 관련 검색 인기값 사용, 1위가 100인 상대값

화면의 인기값은 검색 건수가 아닙니다. 같은 Google Trends 비교 화면 안에서의 상대 관심도입니다.

### 6.7 식품 연관 검색어 정제

연관 검색어·주제에서 다음 절차를 수행합니다.

1. 카테고리 출발 검색어로 `RELATED_QUERIES` 조회
2. 결과가 없으면 설정된 다음 출발 검색어로 재시도
3. Google이 붙인 주제 유형에서 음식·식품·디저트·빵·과일·음료 유형만 유지
4. 카테고리별 `root_terms`와 동일한 총칭 제거
5. 과일 디저트는 `bánh`, `kẹo`, `sấy`, `kem`, `trà`, `sữa`가 포함된 형태만 유지
6. 비식품·장소·행사·동음이의 검색어 제외
7. 한국어 표시명 매핑

이 규칙으로 `mochi` 검색에 섞이는 베개·쿨매트 같은 비식품 결과를 경쟁제품 또는 메뉴 순위로 사용하지 않도록 했습니다.

### 6.8 계절성

- 최소 12개월 이상의 데이터가 있어야 계절성 계산
- 같은 월의 값을 연도와 관계없이 평균
- 가장 높은 월을 100으로 환산
- 지수 90 이상인 달을 피크 월로 표시하되 최대 3개
- 최근 5년 데이터를 사용해 단일 연도의 우연한 급등 영향 완화
- 주 단위로는 정점의 50% 이상이 이어지는 구간을 수요 기간으로 계산
- 반년 이상 높은 상태가 이어지면 특정 시즌이 아닌 `연중 수요`로 분류

### 6.9 지역별 관심도

각 카테고리의 `GEO_MAP_0` 결과를 수집합니다. 카테고리마다 Google의 0~100 스케일이 다르므로 값을 단순 평균하지 않고 지역의 카테고리별 순위를 평균하여 종합 순위를 만듭니다. 특정 카테고리 하나의 큰 값이 전체 지역 순위를 지배하는 문제를 줄이기 위한 방식입니다.

지역 값 0은 오류가 아니라 해당 지역의 검색량이 적다는 뜻으로 정상 데이터로 유지합니다.

## 7. 경쟁제품 조사와 데이터 정제

### 7.1 조사 범위

베트남에서 실제 판매가 확인되는 다음 제품을 조사 대상으로 삼았습니다.

- 모찌·다이후쿠·찹쌀떡 형태의 직접 경쟁제품
- 모찌 아이스크림과 냉장·냉동 모찌
- 선물세트와 대용량 크림 모찌
- 현지 전통 찹쌀과자 중 한정선과 식감·원료·소비 상황이 겹치는 인접 경쟁제품

### 7.2 후보 발굴과 확정 절차

```text
기존 조사표 + Google 색인 후보 + 판매처 직접 검색
        ↓
상품 URL 단위 중복 제거
        ↓
실제 상품 페이지 접속
        ↓
식품 여부·판매 상태·가격·옵션·판매처 확인
        ↓
확정 / 재검토 / 제외 분리
        ↓
동일 제품의 여러 판매처 연결
        ↓
제품 단위와 판매 항목 단위 CSV 생성
```

### 7.3 현재 정제 결과

`data/research_2026-10-26/` 기준:

`competitors_vn.csv` 등 루트의 기존 CSV는 과거 조사와 호환용입니다. 화면은 날짜가 가장 최신인 `research_*` 폴더의 정제 결과를 우선 사용합니다.

### 7.4 식품만 남기는 규칙

다음 항목은 확정 경쟁제품에서 제외합니다.

- 모찌 베개, 쿠션, 쿨매트, 침구 등 비식품
- 캐릭터·장난감·생활용품
- 음식 이름과 우연히 같은 브랜드의 비식품
- 상품 페이지에서 판매 상태를 확인할 수 없는 검색 결과
- 현재 품절·판매 중단 상품
- 같은 URL 또는 같은 제품의 명백한 중복
- 한정선과 비교하기 어려운 일반 식품

검색 제목만 보고 식품으로 확정하지 않습니다. 공개 상품 페이지에서 상품명, 가격, 구매 상태 또는 구조화 데이터를 다시 확인합니다.

### 7.5 판매 확인

판매처별 페이지 구조에 맞춰 다음 신호를 확인합니다.

- 구조화 데이터의 `availability`
- 가격과 구매 버튼
- TikTok Shop 상품 상태와 옵션 재고
- 판매 중단 문구
- 페이지 접근 성공 여부
- 상품 제목과 대표 이미지 URL

상태는 판매 확인, 품절, 판매 중단, 접근 제한, 확인 필요로 분리합니다. 확인되지 않은 후보는 가격이 검색 결과에 보였더라도 확정 목록에 넣지 않습니다.

### 7.6 중복과 제품 통합

- 하나의 실제 제품은 `product_id`로 관리
- 판매처·옵션은 별도의 `listing_id`로 관리
- 같은 제품을 여러 판매처가 판매하면 제품 한 개에 여러 listing 연결
- 브랜드 미확인 마켓플레이스 상품은 근거 없이 서로 합치지 않음
- 알려진 동일 제품만 명시적으로 병합

이 구조로 제품 수와 판매처 수를 혼동하지 않도록 했습니다.

### 7.7 가격 정제

판매 항목에는 다음 원본·계산 필드를 유지합니다.

- 현재 판매가
- 정상가
- 통화(VND)
- 옵션명
- 포장 개수
- 순중량
- 개당 가격
- 100g당 가격
- 배송비 확인 상태
- 가격 확인일

계산식:

```text
개당 가격 = 현재 판매가 ÷ 포장 개수
100g당 가격 = 현재 판매가 ÷ 순중량(g) × 100
```

중량이나 개수가 확인되지 않으면 값을 추정하지 않고 비워 둡니다. 화면에서는 모든 제품에 공통으로 존재하지 않는 100g당 가격 열을 주요 경쟁자 카드에서 제거하고, 확인 가능한 `경쟁 유형`과 `판매가`를 공통 비교 정보로 사용했습니다.

### 7.8 이미지 처리

상품 페이지에서 대표 이미지 URL과 출처 페이지를 기록하지만, 판매처 이미지의 재사용 권한이 확보되지 않았으므로 현재 화면 데이터에는 제품 사진을 전달하지 않습니다. 따라서 `imaged_product_count`는 화면 기준 0입니다.

사진이 없는 것을 데이터 오류로 숨기지 않고 다음 상태로 관리합니다.

- 판매 페이지 대표 이미지 확인
- 서명된 임시 URL일 가능성
- 실제 포장과 육안 대조 미실시
- 이미지 불일치 의심
- 사진 미확인

### 7.9 마케팅 근거

상품 페이지와 공식 채널에서 관찰한 내용을 다음처럼 분리합니다.

- 관찰: 페이지에서 실제로 확인된 표현·구성·가격·판매처
- 해석: 한정선 마케팅에 주는 의미
- 미확인: 실제 구매자 유형, 성과, 판매량처럼 근거가 없는 부분
- 원문 링크: 사용자가 상품 페이지로 직접 이동하여 확인 가능

마케팅 화면은 관찰과 해석을 한국인이 이해하기 쉬운 문장으로 정리하고, 과장된 성과 표현은 사용하지 않습니다.

## 8. 광고 트렌드 조사와 정제

광고 트렌드는 베트남 광고만을 대상으로 하며, 단일 플랫폼의 결과를 전체 시장으로 일반화하지 않도록 여러 출처를 교차 확인했습니다.

사례 파일의 필수 항목:

- 플랫폼
- 브랜드
- 광고 URL
- 광고 형식
- 영상 길이
- 첫 장면·후킹 표현
- 자막 방식
- CTA
- 수집일

정제 과정:

1. 필수 항목 누락 검사
2. 날짜 형식 검사
3. 광고 URL 기준 중복 제거
4. 광고가 아닌 소비자 콘텐츠와 상품 검색 결과를 별도 신호로 분리
5. 반복 확인된 표현만 트렌드 카드로 요약
6. 표본 수와 출처 한계를 화면에 함께 표기

현재 반복 신호는 쫀득한 식감, 익숙한 맛의 새로운 조합, 선물·간식 상황, 제품을 빠르게 보여주는 체험형 영상, 구체적인 구매 정보 등입니다. 이는 확정 성공 공식이 아니라 제작 및 A/B 테스트를 위한 가설입니다.

## 9. 국가·문화 데이터

`content_guidelines_vn.json`에는 문화 대시보드용 출처가 중첩 구조로 저장되어 있습니다. 현재 조사 항목은 다음과 같습니다.

- 베트남 디저트 소비 문화
- 광고 표현과 현지어 표시 주의
- 색상 선호와 맥락
- 연꽃·대나무 등 상징물
- 국기·국장 등 민감 상징 주의
- 선물·개별 포장·소포장 등 패키징 선호
- 전자상거래 및 소비자 행동 참고 자료

색상·숫자·상징의 의미는 모든 베트남 소비자에게 동일한 과학적 사실이 아닙니다. 화면에서는 디자인 참고 정보로만 제공하고, 제품 수량이나 가격을 결정하는 단독 근거로 쓰지 않도록 안내합니다.

`public.py`는 다른 기능에서 사용할 수 있는 다음 인터페이스를 제공합니다.

```python
from market_analysis.public import get_content_guidelines, check_ad_copy

rules = get_content_guidelines("VN")
findings = check_ad_copy("광고 문구", "VN")
```

`check_ad_copy`는 한국어·베트남어·영어 금지 또는 주의 검색어를 NFC 유니코드로 정규화하고 대소문자를 무시하여 탐지합니다. 결과는 법적 판단이 아니라 사전 검토 안내입니다.

## 10. AI 인사이트 생성 절차

### 10.1 입력 검증

서버가 허용한 목표·기간·채널 값만 받습니다. 과일은 설정 파일에서 `mochi_fit=true`인 항목만 선택할 수 있고, 추가 메모는 최대 글자 수를 제한합니다.

### 10.2 AI 이전 서버 계산

AI가 수치를 직접 만들지 않도록 서버가 다음 세 카드를 먼저 계산합니다.

1. 맛 기회
   - 과일 검색 관심도 순위
   - 해당 맛 경쟁제품 수
   - 검색 피크 월
2. 가격 위치
   - 중량이 확인된 제품의 100g당 가격
   - 보관 방식별 가격 분포
3. 채널 기회
   - 경쟁 판매 항목의 채널 분포
   - 공개된 플랫폼 점유율 자료와 비교

현재 경쟁사 UI에서는 가격 구성 탭을 제거했지만, 가격 분포 계산은 AI 근거 카드에서 사용할 수 있도록 서비스에 유지되어 있습니다.

### 10.3 근거 태그

각 근거에는 태그, 문장, 출처, 기준일을 붙입니다. AI가 작성한 문장이 어떤 자료에서 나왔는지 다시 확인하기 위한 구조입니다.

### 10.4 생성 후 검증

AI 출력의 숫자와 근거 태그를 서버 근거 목록과 비교합니다. 확인되지 않은 근거·수치·의견은 삭제하고 `dropped` 수로 기록합니다. 경쟁사 데이터가 없거나 공공 데이터가 부족하면 한계 문구를 결과에 자동 추가합니다.

### 10.5 저장 정책

현재 `/api/insight`의 POST 결과는 서버 DB에 저장하지 않습니다. 사용자가 요청할 때 생성하여 응답하는 구조입니다.

## 13. 데이터 상태와 신뢰도 표시

트렌드 데이터 상태:

- `fresh`: 권장 갱신 주기 안의 정상 데이터
- `delayed`: 갱신 주기를 지난 데이터
- `partial`: 일부 영역 또는 일부 항목 데이터 부족
- `empty`: 수집 데이터 없음
- `insufficient`: 커버리지·표본·관심도 기준 미달

경쟁제품 상태:

- 판매 확인
- 품절
- 판매 중단
- 접근 제한
- 판매 여부 확인 필요
- 사진 확인 필요
- 범위 제외

확인되지 않은 값은 `0`이나 임의 문구로 채우지 않고 비워 두거나 확인 필요로 표시합니다.

## 16. 반드시 설명해야 할 한계

1. Google Trends는 절대 검색량이 아니라 상대 관심도임
2. 검색어 표현과 비교 묶음이 바뀌면 0~100 지수도 달라짐
3. 카테고리 검색어는 시장 전체가 아니라 대표 검색어 묶음임
4. Shopee·Lazada·TikTok Shop은 로그인·접근 제한·동적 가격 때문에 전수조사가 아님
5. 가격은 확인일의 표시 가격이며 쿠폰·배송비·회원가가 다를 수 있음
6. 판매량이 공개되지 않은 제품이 많아 제품 수·판매처 수를 공급 신호로 사용함
7. 광고 표본은 플랫폼이 공개한 일부 사례이며 전체 광고 시장을 대표하지 않음
8. 문화 정보는 마케팅 참고이며 법률 자문이나 모든 소비자의 보편적 선호가 아님
9. 판매처 이미지에는 저작권·사용권이 있으므로 화면 재사용 전에 허가 확인이 필요함
10. AI 결과는 확인된 근거를 바탕으로 한 실행 가설이며 최종 사업 판단이 아님

## 17. 다른 사람에게 설명하는 1분 발표문

> 현지 시장 분석은 베트남에서 한정선 찹쌀떡을 판매하기 위해 검색 수요, 경쟁제품, 문화, 광고 사례를 한 화면에 모은 기능입니다. 검색 데이터는 SerpApi의 Google Trends 결과를 사용하되 원본을 먼저 보관하고, 최근 12주와 전년 동기를 비교해 관심도와 증감률을 계산했습니다. 경쟁제품은 Google 검색 결과만 믿지 않고 실제 상품 페이지에서 식품 여부, 판매 상태, 가격과 판매처를 확인해 58개 제품과 85개 판매 항목으로 정리했습니다. 비식품·품절·확인 불가 항목은 별도 제외 또는 재검토 목록으로 분리했습니다. 광고와 문화 정보도 출처와 확인일을 같이 저장했습니다. 마지막으로 사용자가 목표와 기간, 채널만 선택하면 서버가 이 근거들을 먼저 계산해 OpenAI에 전달하고, AI가 만든 숫자와 근거를 다시 검사한 뒤 실행안을 보여줍니다.

## 18. 다른 사람에게 설명하는 5분 순서

1. **문제 정의**  
   베트남 진출 판단에 필요한 자료가 검색·쇼핑몰·광고 플랫폼·공공자료에 흩어져 있었음

2. **데이터 수집**  
   SerpApi Google Trends, World Bank, 공휴일 API, 공개 상품 페이지, 광고 라이브러리를 사용함

3. **데이터 정제**  
   누락값을 0으로 만들지 않고, 식품만 남기고, 중복 제품과 판매 항목을 분리하고, 판매 미확인 후보를 제외함

4. **분석 기준**  
   최근 12주 관심도, 전년 동기 증감률, 월별 피크, 지역 순위, 실제 표시 가격, 유통채널과 마케팅 관찰을 사용함

5. **화면 구현**  
   국가·문화, 트렌드, 경쟁사, AI 인사이트 네 탭에서 마케터가 바로 비교할 수 있게 구성함

6. **AI 활용**  
   AI가 원데이터를 추측하게 하지 않고 서버가 만든 근거만 전달하며, 결과도 근거 태그와 숫자로 재검증함

7. **한계 공개**  
   상대 지수, 플랫폼 표본, 가격 시점, 이미지 권리, 문화 정보의 적용 범위를 화면과 문서에 명시함
