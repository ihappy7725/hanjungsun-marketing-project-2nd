# 인플루언서 마케팅 — 한정선 베트남 크리에이터 협업 관리

> 한정선 찹쌀떡의 베트남 진출을 위해 현지 인플루언서 **발굴 → 검증·등록 → 협업 제안 → 회신·일정 정리 → 단가 기록 → 자료 반출**까지 한곳에서 처리하는 인플루언서 마케팅 탭의 기능 문서입니다.
>
> 담당: 진혁 · 문서 버전: **Ver_023** (2026-10-26, 팀 의견 10건 반영 '덜어내기': 진행 단계 4칸·타깃 한 칸·파일 자동 정제 화면 제외·단가 입력 접힘) · 담당 폴더: `influencer_marketing/`
>
> **Ver_023 화면이 아래 3장 이하 설명(Ver_022까지 기준)과 다른 부분은 맨 아래 'Ver_023' 항목이 우선입니다.**
>
> 개인 브랜치(`Influencer`)에서 구현과 시험을 마쳤고, `premain` 머지 전입니다. 외부 API는 **가짜 응답(Mock) 시험**을 마쳤고, YouTube는 담당자 PC에서 실제 키로 검색·인기 순위 동작을 확인했습니다. 나머지 실제 환경 확인 항목은 11장에 있습니다.

## 먼저 읽기

- 이 문서는 최상위 `README.md`의 인플루언서 마케팅 범위를 구체화합니다. 공통 구조·데이터 소유권·Git 규칙은 최상위 README가 우선입니다.
- 대시보드 화면은 **한국어**, 인플루언서에게 보내는 메일은 **베트남어·영어·한국어(검토용)** 입니다.
- 협업 제안은 **메일 초안 생성과 복사까지**입니다. 자동 발송은 하지 않습니다.
- **외부 API 키가 하나도 없어도 기본 기능은 모두 동작합니다.** 키가 없는 서비스는 꺼져 있거나 접혀 있을 뿐입니다.
- 크롤링(사이트 화면 자동 수집), 비공식 로그인 자동화, 접근 제한 우회는 **하지 않습니다.** 공식 API와 사용자가 확인·보유한 자료만 씁니다.
- 가상 인물·견적은 DB에 **시연 데이터**(`is_demo`)로 구분해 저장하고, `public.py`도 `is_demo`를 그대로 넘깁니다.
- 팀 통합본에서는 화면의 '(시연)' 표시, 시연 데이터 안내 배너·[시연 데이터 지우기] 버튼, '시연용 파일' 체크칸이 **화면에서 숨겨져 있습니다.** 그래서 지금은 화면만 보고 시연 데이터를 구분할 수 없고, 시연용 CSV를 올리면 일반 데이터로 등록됩니다(11장 확인 항목).

## 2. 사용 흐름

### 2.1 기본 흐름

1. **[발굴]** 에서 후보를 찾습니다. 하위 탭 중 편한 것을 씁니다.
   - **1. 후보 탐색**: NoxInfluencer 참고 자료 또는 YouTube Data API로 일괄 조회 (정렬: 기본 / 인기순 / 조회수 많은 순)
   - **2. 파일 자동 정제**: 에이전시·SaaS 엑셀(CSV) 숫자·열 이름 자동 정리
   - **3. 직접 등록**: TikTok One 등 화면에서 확인한 값 입력 → 중복 확인
2. 결과에서 출처·신뢰도·등록 여부를 보고 골라 **[선택한 후보 등록]** → "후보" 상태로 들어갑니다. 같은 계정은 자동으로 건너뜁니다.
3. **[제안 메일]** 에서 저장된 이벤트를 불러오고 메일을 확인·번역 대조한 뒤 복사해 보냅니다 → [제안 발송으로 표시].
4. **[회신 정리]** 에 받은 회신을 붙여 넣어 자동 정리 → 확인 후 저장.
5. **[회신 정리]** 오른쪽(또는 [요약])에서 촬영일 확정 → **[광고 단가]** 에 견적·계약가 기록 → 각 탭의 CSV 버튼·오른쪽 위 [보고서]로 CSV·PDF.

### 2.2 API 키가 없을 때

[발굴] → 1. 후보 탐색에서 **NoxInfluencer 참고 자료**(키 필요 없음)로 찾거나, 3. 직접 등록의 [TikTok One 열기] → 화면에서 본 숫자를 적어 등록하거나, **발굴 후보 CSV 양식**에 채워 2. 파일 자동 정제로 올립니다.

### 2.3 기념일 캠페인과 연결

HOME 캘린더에서 `/influencer_marketing/?event_id=...` 로 들어오면 그 기념일에 연결된 협업만 보이고, 이 상태에서 등록한 인플루언서는 기념일이 자동으로 연결됩니다.

## 3. 탭별 기능

### 3.1 요약

Ver_017에서 "팀장·발표자가 30초 안에 읽는 화면"을 기준으로 다시 짰습니다.

**계산 범위 (Ver_018)**: 맨 위 띠에서 **[실제 데이터만] / [시연 데이터 포함]** 을 고릅니다. 시연 데이터가 있으면 기본은 **시연 데이터 포함**(발표용)이고, 그동안 노란 띠에 "시연 데이터 포함 중 · 가상 크리에이터 N명·견적 N건(실제 인물 아님)"을 계속 보여 줍니다. [실제 데이터만]을 누르면 시연 데이터를 모두 빼고 다시 계산합니다. 시연 데이터가 없으면 띠는 숨고 실제 데이터만 셉니다. 시연 크리에이터 A~G의 채널 주소는 예약 도메인 `example.com`의 가짜 주소라 실제 계정과 겹치지 않습니다.

| 칸 | 내용 |
| --- | --- |
| 진행 단계 | 1. 후보 → 2. 주소 확인(프로필 주소 있음, '주소 직접 확인 필요' 제외) → 3. 제안 → 4. 회신 → 5. 확정(계약 확정·촬영·게시). 오른쪽 위 %는 앞 단계 대비 |
| 예산 현황 | 견적 합계·계약 합계·평균 단가(게시물 1건, USD)와 VND 환산, 환율 입력일. 이상값은 합계에서 빼고 개수 표시 |
| 데이터 신뢰도 | 대표 채널 지표 기준 검증(공식 API·직접 확인) / 추정(SaaS·순위 사이트·제출 자료) / 미확인(주소·지표 없음) 비율 |
| 칼퇴 지표 | 이번 달 파일 자동 정제로 아낀 시간(추정, 1칸 10초 기준)·자동 정리 칸·중복 제외 건수·파일 수 |
| 오늘의 할 일 Top5 | 사람별 나열 대신 묶어서 개수로: 회신 확인 필요 → 회신 지연(7일) → 촬영일 확정 대기 → 14일 안 촬영 → 단가 이상값 → 주소 직접 확인 필요 → 제안 미발송 → 지표 기준일 45일 지남. 급한 5개만 보이고 [이동]으로 해당 탭(주소 확인은 필터가 켜진 목록)으로 갑니다 |

| 14일 일정 | 촬영 확정·게시 예정·협의 가능일, D-day, 같은 날 겹침 |
| 구성 | 타깃 그룹 / 대표 플랫폼 / 규모를 버튼으로 바꿔 보는 막대 하나(예전 분포 막대 3개를 합침) |

### 3.2 인플루언서

| 항목 | 기준 |
| --- | --- |
| 기본 정보 | 이름(필수), 대표 핸들, 분야(디저트·먹방, 맛집 리뷰, 라이프스타일, 가족·육아, K-컬처, 뷰티, 여행, 기타), 지역(호치민·하노이·다낭·기타), 이메일, Zalo, 매니지먼트 |

- 규모 등급: Nano 1천~1만 / Micro 1만~5만 / Mid 5만~10만 / Macro 10만~50만 / Mega 50만 이상
- 지표가 바뀔 때마다 **지표 기록**이 쌓여 편집 창에서 시점별로 비교할 수 있습니다.
- **Ver_017**: 맨 위에 **인플루언서 기준** 한 줄(`팔로워 1천+ (Nano~Mega) · 베트남(인): 식품(맛집·먹방), 간식·디저트, K-푸드·K-컬처, 라이프스타일 / 한국(인): 다낭 여행 유튜버`, 타깃 그룹은 `discovery.SEGMENTS`에서 자동으로 만듦), **'주소 직접 확인 필요만 보기'** 체크, 표는 화면 높이 안에서만 스크롤(머리글 고정), 표 아래 **[목록 CSV 내보내기]·[가져오기용 빈 양식]·[YouTube 지표 일괄 갱신]**. 예전 'YouTube에서 후보 찾기' 접힘은 [발굴] → 1. 후보 탐색(YouTube Data API)과 같은 기능이라 뺐습니다(`/api/youtube/search`·`add-candidate` 경로는 그대로).

- **화면에서 뺀 것(코드는 유지)**: Phyllo·Modash·HypeAuditor·TikTok One 조회 선택지, '선택 연동 서비스 보기' 접힘, 콘텐츠 카테고리 버튼(타깃 그룹이 정한 카테고리를 내부에서 그대로 사용), 별도 '인기 순위' 패널(→ 정렬 '인기순'), Phyllo 안내 문구, TikTok One '검색 기준 복사'. `discovery.py`·`external_api.py`의 어댑터와 `/api/discovery/ranking`·`/api/integrations/*` 경로는 그대로라, 계약·권한이 생기면 화면만 다시 붙이면 됩니다.
- **칼퇴 지표**: 파일을 올릴 때마다 자동 정리 칸(숫자 표기 정리 + 빈 수집일 채움)과 파일 안 중복 제외 건수를 이번 달 누적에 더합니다(설정 키 `time_saved`, 최근 12개월). **같은 내용의 파일은 같은 달에 한 번만** 셉니다(파일 내용 대신 짧은 해시만 저장). 1칸 10초는 추정 기준이며 화면에 함께 표시합니다.

**① 조건 검색** — 플랫폼, 국가(베트남), 콘텐츠 언어, 팔로워 최소·최대, 최소 조회수, 최소 참여율, 베트남 시청자 비중, 카테고리, YouTube 검색어(베트남어 검색어 예시 14개 버튼 — 한국어 뜻 표시, 누르면 입력)

**② 인기 순위 (공식 API)** — Ver_017에서 화면 패널은 빼고 1. 후보 탐색의 정렬 '인기순'으로 대신합니다. 서버 기능·경로는 유지.

**④ 후보 직접 입력** — 계정 주소 입력 → **[주소로 지표 채우기]** (YouTube는 공식 API로 이름·구독자·조회수 중앙값·참여율, TikTok·Instagram은 Phyllo 권한이 있을 때. Facebook은 수동) → [중복 확인] → [후보로 등록]. 출처는 자동으로 "YouTube API"·"Phyllo"로 바뀌고, 직접 본 값은 "TikTok One 화면 확인·채널에서 직접 확인·인플루언서 제출·에이전시 자료" 중에서 고릅니다.

**⑤ 파일로 여러 명 가져오기 (자동 정제)** — CSV·TSV(5MB·2,000행)를 올리면 저장 전 미리보기로 보여 줍니다.

| 정제 | 처리 |
| --- | --- |
| 인코딩·구분자 | UTF-8, CP949(한국어 엑셀), UTF-16, CP1258 / 쉼표·탭·세미콜론 자동 판별 |
| 열 이름 | 한국어·영어·베트남어 열 이름 자동 대응, 성장률·사진 주소 열은 사용 안 함 |
| 숫자·비율·날짜 | `1.2M`, `12,5K`, `1.234.567`, `15 triệu`, `3만` / 0~1 비율 → % / `dd/mm/yyyy` → `YYYY-MM-DD`. 읽지 못한 값은 비우고 사유 표시 |
| 조회수 기준 | 중앙값 열만 중앙값 칸에, 기준 없는 `Views`는 평균 칸 + "조회수 기준 불명" 메모 |
| 중복·출처·시연 | 파일 안 중복 제외, 기존 계정 "등록됨", 파일 출처·제공처 선택, "시연용 파일" 체크 시 시연 데이터로 등록(팀 통합본에서는 체크칸이 숨겨져 있음) |

- 엑셀(.xlsx)은 'CSV UTF-8'로 저장해서 올립니다(대시보드에서 직접 읽지 않음).

**중복 기준** — 같은 플랫폼 + 같은 계정이면 중복입니다. 주소 형식·대소문자가 달라도 같은 계정으로 봅니다(`https://www.tiktok.com/@BanhNgon.VN?lang=vi` = `@banhngon.vn`). YouTube 채널 ID 주소와 핸들 주소는 같은 채널로 알아보지 못하니 같은 형식으로 저장합니다.

### 3.3-0 참고 자료 CSV로 찾기 (Ver_015~016)

- [발굴] **조회할 곳**에 `influencer_marketing/reference_data/` 폴더의 CSV가 선택지로 나옵니다. 지금은 **NoxInfluencer (2026/10/26 기준, 순위 갱신 2026/10/24) · 파일 287개** 하나입니다(Ver_016에서 발표용 가상 데이터 선택지는 뺐습니다).
- 고르고 [후보 검색]을 누르면 **외부 사이트에 접속하지 않고 파일만 읽어** 지금 고른 플랫폼의 **실제 계정**을 보여 줍니다(연두 → 노랑 → 회색). **제외(D) 등급은 기본으로 숨기고**, [제외(D) 등급도 보기]로 볼 수 있습니다.
- **이름 표시(Ver_016)**: 계정 ID를 알면 `@계정ID`를 먼저, 모르면 **검색하기 쉬운 이름**(꾸민 글꼴·이모지를 일반 글자로, 예: `𝙃𝙤̀𝙖 𝙍𝙪𝙗𝙮` → `Hòa Ruby`)을 보여 주고, 원래 표기는 'Nox 표기'로 작게 남깁니다. 등록할 때도 이 이름으로 저장합니다.
- **링크(Ver_016)**: 주소를 확인한 계정은 이름이 **프로필 링크**입니다. 모든 계정에 **직접 찾기: TikTok · Instagram · YouTube · Facebook · Google** 링크가 붙어, 누르면 각 사이트의 검색 결과가 새 창으로 열립니다(사용자가 직접 여는 링크이며 자동 수집하지 않음).
- **주소 없는 계정도 체크·등록 가능(Ver_016)**: '플랫폼+이름'으로 중복을 확인하고, **'주소 직접 확인 필요'** 로 표시합니다(결과 표·인플루언서 목록 칩·메모 `[주소 직접 확인 필요]`·편집 창 안내). 편집 창에서 해당 플랫폼 주소를 넣고 저장하면 표시가 사라지고, 그때부터 주소 기준 중복 확인·지표 채우기가 됩니다. 참고 자료가 아닌 직접 입력은 지금처럼 주소가 필요합니다.
- **인플루언서 기준 = Nano(팔로워 1천) 이상(Ver_016)**: 발굴 기본 조건은 최소 팔로워 1,000, 최대 팔로워 비움입니다. 팔로워가 1천 미만으로 확인된 계정은 모든 조회 방식에서 결과에서 빼고 개수를 알려 줍니다. 팔로워를 모르는 계정은 빼지 않고 '확인 불가'로 둡니다(0으로 보지 않음).
- **분야**: 참고 자료 계정의 분야는 화면의 카테고리 버튼과 상관없이 타깃 그룹의 기본 분야(없으면 '기타')로 저장합니다.
- 결과 표에 분류 색 칩·식품 관련성 점수·Nox 순위·팔로워 출처(기준일)가 보이고, 순위 계정과 이름만 같은 계정은 "같은 계정인지 확인 필요"로 표시합니다.
- **CSV 넣는 법**: 폴더에 CSV를 복사하고 `sources.json`에 `file`·`label`·`as_of`·`kind`를 추가 → 새로고침. 자세한 방법은 `reference_data/README.md`.
- NoxInfluencer 자료는 팀 내부 참고용입니다(저장소 비공개 유지, 팀 밖 공유 금지).

- **번역해서 대조하기 (6방향)**: 한→베, 베→한, 영→베, 베→영, 한→영, 영→한 버튼을 누르면 **Google 번역이 새 창으로** 해당 언어 쌍과 글이 채워진 채 열립니다(무료·키 없음).
  - ① 미리보기 메일(제목+본문)을 번역 ② 번역 결과를 대조 칸에 붙여 넣고 반대 방향으로 다시 번역 → 원문과 비교
  - 5,000자가 넘으면 글을 복사하고 빈 번역 창을 엽니다. 기계 번역이라 발송 전 현지 검수를 권장합니다.

### 3.5 회신 정리

- 받은 메일·Zalo 메시지를 붙여 넣으면 가능 여부(A/B/C, có thể 등), **베트남식 날짜(dd/mm)**, 비용("15 triệu", "6,5 triệu")을 읽어 채웁니다. 헷갈리는 항목은 **"확인 필요"** 로 표시합니다.
- **번호 항목별로 읽습니다 (Ver_014).** 제안 메일의 회신 양식 번호대로 1번=가능 여부, 2번=협의 가능일, 3번=촬영 가능일, 4번=게시 가능일, 5번=희망 비용, 6번=기타 의견으로 읽습니다. `1)` 뿐 아니라 `1.` `1:` 형식과 `**굵은 글씨**` 표시도 인식합니다.
- **기타 의견 칸에는 6번 내용만** 들어갑니다(메일 제목·인사말 제외). 6번이 없으면 비워 두고 '확인할 점'에 알립니다. 번호 없이 쓴 회신은 'Ý kiến khác:' / 'Other:' / '기타 의견:' 뒤의 내용을 넣습니다.
- **6번(기타 의견) 속 날짜는 일정에 넣지 않습니다.** 예: "샘플을 01/12까지 받고 싶어요"의 01/12는 협의·촬영일이 아니므로 '확인할 점'에 "기타 의견 속 날짜(01/12/2026)는 일정에 넣지 않았어요"라고 표시합니다.
- 5번을 숫자로 읽지 못하면(예: "Thỏa thuận(협의)") 비워 두고 알립니다. "Không áp dụng / 없음" 같은 답은 알리지 않습니다.
- **번역 버튼**: 기타 의견 칸 아래 [기타 의견 한국어로 번역], [회신 원문 전체 한국어로 번역]을 누르면 Google 번역이 새 창으로 열립니다(무료·키 없음, 언어 자동 감지 → 한국어). 저장되는 내용은 원문 그대로입니다. 5,000자가 넘으면 글을 복사하고 빈 번역 창만 엽니다.
- **촬영일 확정 (Ver_017, [일정] 탭에서 옮김)**: 오른쪽 위 '촬영일 확정'에 회신에 적힌 촬영 가능일이 버튼으로 나오고, 누르면 확정됩니다. 같은 날 다른 촬영 확정이 있으면 빨간 테두리로 알립니다. 옆의 **[일정 CSV]** 로 협의·촬영·게시 날짜를 내려받습니다.
- 오른쪽 **받은 회신**의 [열기]를 누르면 왼쪽 입력칸에 불러오고, 해당 줄 강조·화면 이동·안내가 나옵니다.
- **수정**: 불러온 뒤 고쳐서 [회신 수정 저장]. **삭제**: [회신 삭제]를 두 번 누르면 회신이 지워지고 상태가 '제안 발송'(발송 기록이 없으면 '후보')으로 돌아갑니다. 계약 확정 이후 상태와 확정 촬영일·게시일은 그대로 둡니다.

- **Ver_011A는 인플루언서 테이블에 `segment` 칸을 추가했습니다.** `init-db`(`db.create_all`)는 이미 있는 표에 새 칸을 추가하지 않아서, 예전 DB를 쓰면 `no such column: ...segment` 오류가 났습니다.
- **Ver_013부터는 자동으로 보완합니다.** 서버가 켜진 뒤 첫 요청 때 `models.ensure_columns()`가 한 번 실행되어, 표가 있는데 칸이 빠져 있으면 그 칸만 `ALTER TABLE ... ADD COLUMN`으로 추가합니다. **기존 데이터와 다른 탭 표는 그대로**이고, 표가 아직 없으면(init-db 전) 아무것도 하지 않습니다. 확인에 실패해도 다른 탭은 멈추지 않고 경고 로그만 남깁니다.
- 앞으로 칸을 추가할 때는 `models.py`의 `ADDED_COLUMNS`에 (표 이름, 칸 이름, 칸 정의)를 한 줄 추가합니다.
- 4개 테이블은 `init-db` 때 만들어지며, 표 자체가 없는 아주 예전 로컬 DB(지표 기록 테이블 없음)는 `init-db`를 한 번 실행하면 빠진 표가 만들어집니다(기존 표·데이터는 유지).
