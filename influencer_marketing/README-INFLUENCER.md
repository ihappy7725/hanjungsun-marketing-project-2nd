# 인플루언서 마케팅 — 한정선 베트남 크리에이터 협업 관리

> 한정선 찹쌀떡의 베트남 진출을 위해 현지 인플루언서 **발굴부터 검증·등록, 협업 제안, 회신·일정 정리, 단가 기록, 자료 반출**까지 처리하는 인플루언서 마케팅 탭의 기능 문서입니다. 담당: 진혁 · 문서 버전: Ver_003 (2026-10-23, API 확장 + 베트남어 검색어 예시·선택 연동 접힘 + 단가 그래프 출처 표기·탭 이름 '연결 여부 확인')
>
> 이 탭은 **개인 브랜치에서 구현과 시험을 마친 상태**입니다. 아직 `premain`에 머지되지 않았습니다. 외부 API는 **가짜 응답(Mock) 시험**만 마쳤고, 실제 키로는 확인 전입니다. 항목별 상태를 아래에 표시합니다.

## 먼저 읽기

- 이 문서는 전체 `README.md`의 인플루언서 마케팅 범위를 구체화합니다. 공통 아키텍처·데이터 소유권·Git 규칙은 전체 README를 따릅니다.
- 사용자는 한정선 마케팅 담당자이며, 대시보드 화면은 **한국어**입니다. 인플루언서에게 보내는 메일은 베트남어·영어·한국어(검토용)로 만듭니다.
- 협업 제안은 **메일 초안 생성과 복사까지**입니다. 실제 메일 자동 발송은 범위 밖입니다.
- 외부 API 키가 하나도 없어도 모든 기본 기능이 동작합니다. 키가 없는 서비스는 "키 없음"으로 꺼져 있을 뿐입니다.
- 화면의 가상 인물·견적은 모두 **시연 데이터**로 표시하며, 버튼 하나로 지울 수 있습니다.

## 1. 이 탭이 해결할 문제

베트남은 인스타그램보다 **페이스북·틱톡** 중심이고, 인플루언서 지표와 광고 단가가 공개되어 있지 않습니다. 협업 연락도 메일·Zalo로 흩어집니다. 이 탭은 후보 발굴부터 단가까지 한곳에 모아 **누구에게 무엇을 해야 하는지** 바로 판단하게 합니다.

이 탭에서 다음 질문에 답할 수 있어야 합니다.

1. 우리 제품에 맞는 베트남 인플루언서를 어디서, 어떤 기준으로 찾는가?
2. 그 숫자(팔로워·조회수·참여율)는 어디서 왔고, 얼마나 믿을 수 있는가?
3. 누구에게 제안을 보냈고, 누가 아직 회신하지 않았는가?
4. 회신한 사람은 언제 협의·촬영·게시가 가능한가?
5. 받은 견적은 시장 참고가보다 비싼가, 싼가?
6. 이 내용을 보고용 파일로 바로 뽑을 수 있는가?

## 2. 사용 시나리오

### 2.1 발굴부터 협업까지

1. **[발굴]** 탭에서 플랫폼·국가(베트남)·카테고리·팔로워·조회수·참여율·베트남 시청자 비중을 정합니다.
2. 키가 있는 서비스(YouTube·Modash·HypeAuditor)로 **[후보 검색]**을 누릅니다. 키가 없으면 **TikTok One 연계**로 같은 기준을 복사해 TikTok One에서 찾습니다.
3. 결과에서 프로필 링크, 지표, **출처·신뢰도**, **등록 여부**를 확인하고 후보를 고릅니다.
4. **[선택한 후보 등록]** → 같은 계정은 건너뛰고, 새 계정만 "후보" 상태로 인플루언서 목록에 들어갑니다.
5. 이후는 기존 흐름 그대로입니다: [제안 메일] → 회신 → [회신 정리] → [일정] 확정 → [광고 단가] 기록 → [내보내기].

### 2.2 API 없이 진행 (기본 경로)

1. [발굴] → **[TikTok One 열기]**, **[검색 기준 복사]**
2. TikTok One에서 찾은 계정의 숫자를 **후보 직접 입력**에 적고 [중복 확인] → [후보로 등록]
3. 여러 명이면 **발굴 후보 CSV 양식**에 채워 [CSV 올리기] → 미리보기에서 골라 등록

### 2.3 기념일 캠페인과 연결

1. HOME 캘린더의 기념일에서 `/influencer_marketing/?event_id=...` 주소로 들어옵니다.
2. 해당 기념일에 연결된 협업만 걸러서 보입니다.
3. 이 상태에서 새로 등록하는 인플루언서(발굴 등록 포함)는 그 기념일이 자동으로 연결됩니다.

### 지켜야 할 원칙

- 다른 탭의 테이블을 직접 읽거나 수정하지 않습니다. `market_analysis/public.py`만 읽습니다.
- 기념일 정보는 복사하지 않고 `event_id`만 저장합니다. 기념일 함수가 없거나 오류가 나도 화면은 멈추지 않습니다.
- 공개 함수는 오류가 나도 빈 목록(`[]`)을 돌려줍니다. 반환 필드는 지우지 않고 추가만 합니다.
- **기존 기능·함수명·URL·필드·테이블은 지우거나 바꾸지 않았습니다.** 이번 확장은 모두 추가입니다.

## 4. I01 — 인플루언서 리스트·지표 관리

### 4.1 인플루언서 정보

| 항목 | 기준 |
| --- | --- |
| 이름 | 필수 |
| 대표 핸들·분야·활동 지역 | 분야: 디저트·먹방, 맛집 리뷰, 라이프스타일, 가족·육아, K-컬처, 뷰티, 여행, 기타 / 지역: 호치민·하노이·다낭·기타 |
| 연락처 | 이메일, Zalo, 매니지먼트·에이전시 |
| 채널 지표 | TikTok·Facebook·YouTube·Instagram별 팔로워, 조회수 중앙값, 채널 주소 (+ 13장의 추가 지표) |
| 지표 기준일·출처 | 직접 확인, 인플루언서 제출, YouTube API, Phyllo, Instagram API, TikTok One, 에이전시 자료, Modash, HypeAuditor |
| 진행 상태 | 후보 → 제안 발송 → 회신 받음 → 협상 중 → 계약 확정 → 촬영 완료 → 게시 완료 / 불가·보류 |
| 연결 기념일 | `event_id` (선택) |
| 날짜 | 제안 발송일, 확정 촬영일, 게시 예정일 |

### 4.2 기준과 계산

- **조회수는 평균이 아닌 중앙값**을 씁니다. 광고가 아닌 최근 게시물 10~20개 기준이며, 대박 영상 한두 개로 숫자가 부풀려지는 것을 막습니다.
- 평균만 아는 경우는 **"평균 조회수" 칸에 따로** 저장하고, 중앙값 칸에는 넣지 않습니다.
- **대표 채널**은 팔로워가 가장 많은 채널입니다.
- **규모 등급**: Nano 1천~1만 / Micro 1만~5만 / Mid 5만~10만 / Macro 10만~50만 / Mega 50만 이상.
- 확정 촬영일을 넣으면 상태가 자동으로 "계약 확정"으로 바뀝니다.
- 지표 기준일이 45일 넘게 지나면 [요약]에 "지표 갱신" 할 일이 뜹니다.

## 5. I02 — 협업 제안 메일 자동 작성

- 캠페인 정보(브랜드, 제품명 3개 언어, 회사명, 보내는 사람, 회신 이메일·Zalo, 기간, 회신 기한, 비용 문구, 광고 가이드라인)를 한 번 저장하면 모든 메일에 들어갑니다.
- 메일 끝에 **번호가 붙은 회신 양식**: ① 가능 여부 A/B/C ② 협의 가능일 ③ 촬영 가능일 ④ 게시 가능일 ⑤ 희망 비용(VND) ⑥ 기타.
- 메일 앱이 메일 속 입력 양식을 막기 때문에 본문에 버튼을 넣지 않고, 정해진 양식으로 회신받아 I03에서 자동 정리합니다.
- 기본 광고 가이드라인에 베트남 개정 광고법(Law No. 75/2025/QH15, 2026-01-01 시행)의 핵심을 반영했습니다: 게시 전·중 광고 표시, 직접 써 본 제품만 홍보, 식품 효능 표현 금지.
- **발송은 복사해서 사용자가 직접**. 자동 발송은 이번 범위에서 제외했습니다.

## 6. I03 — 회신 자동 정리

- `1) A/B/C` 답변 또는 "có thể / không thể / điều kiện" 같은 표현으로 가능 여부를 읽습니다.
- 날짜는 **베트남식 일/월(dd/mm)**로 읽습니다. 예: `06/11` → 11월 6일. 연도가 없으면 올해, 60일 넘게 지났으면 내년.
- "15 triệu", "6,5 triệu", "15.000.000 đ"를 VND 숫자로 바꿉니다.
- 헷갈리는 날짜·가능 여부를 못 찾은 경우는 **"확인 필요"**로 표시하고, 사람이 확인해야 저장됩니다.

## 7. I04 — 협업 일정 달력

- 협의 가능일(점선), 촬영 가능일(연한 남색), **촬영 확정일(팥색)**, 게시 예정일(연한 초록)을 한 달력에 표시합니다.
- 같은 날 촬영 확정이 2건 이상이면 빨간 테두리로 표시합니다.
- 날짜는 **베트남 시간(UTC+7)** 기준입니다. 한국은 2시간 빠릅니다.

## 8. I05 — 광고 단가 기록·비교

| 구분 | 의미 |
| --- | --- |
| 공개 참고가 | 대행사가 홈페이지에 공개한 가격. 실제 계약가 아님 |
| 견적 | 인플루언서·에이전시가 제시한 금액 |
| 계약가 | 계약서에 적힌 최종 금액 |

- 공개 참고가 (Best Martech 2026, 게시물 1건, USD, VAT·광고비 별도): Nano 40–190 / Micro 190–380 / Mid 380–765 / Macro 765–1,910 / Mega 1,910부터.
- 단가 그래프 바로 아래에 **출처를 작은 회색 글씨로** 표기합니다: 네모 칸(공개 참고가 범위)은 Best Martech 2026 가격표를 옮긴 값이며 평균값·계약가가 아니고, 점은 이 탭에 기록한 견적·계약가입니다.
- 참고 계산: 조회 1천 회당 비용 = 금액 ÷ 조회수 중앙값 × 1,000 (VND). **예산·광고비 공식은 KPI(민지) 담당**입니다.
- **SaaS가 주는 추정 광고비는 이 표에 넣지 않습니다.** 발굴 결과에 "SaaS 추정 광고비 (계약가 아님)"로만 보여 줍니다.

### 11.1 검색 조건

| 조건 | 화면 | YouTube | Modash | HypeAuditor |
| --- | --- | --- | --- | --- |
| 플랫폼 | TikTok / Instagram / YouTube | YouTube만 | 3개 | 3개 |
| 국가/지역 | 베트남 / 제한 없음 | 지역 우선(regionCode=VN) | 지원 | 지원 |

| 최소 조회수 | 숫자 | 확인 불가 | 지원 (중앙값) | 지원 (평균) |

- **베트남어 검색어 예시**: YouTube 검색칸(인플루언서 탭·발굴 탭) 아래에 자주 쓰는 베트남어 검색어 14개를 한국어 뜻과 함께 보여 줍니다. 누르면 검색칸에 들어가고, 여러 개 고르면 `|`(또는)로 이어집니다. 다시 누르면 빠집니다.
  예: `bánh mochi Hàn Quốc`(한국 모찌·찹쌀떡), `ăn thử đồ Hàn`(한국 음식 먹어 보기), `món tráng miệng`(디저트), `review quán ăn Sài Gòn`(호치민 맛집 리뷰), `quà Tết`(뗏·설 선물)
- API가 거르지 못한 조건은 결과에서 **한 번 더 적용**합니다. 값이 없어 확인할 수 없는 조건은 **빼지 않고 "확인 불가"로 표시**합니다.
- Modash·HypeAuditor는 카테고리를 분류 ID로 받아야 해서 이번에는 적용하지 않았습니다(결과 화면에 안내).

### 11.2 결과에서 할 수 있는 일

1. 프로필 링크로 계정 확인
2. 팔로워·조회수(**중앙값/평균 구분 표시**)·참여율·베트남 시청자 비중
3. **출처·제공업체·신뢰도·수집일** 확인
4. **등록 여부** (같은 플랫폼의 같은 계정이 이미 있으면 "등록됨"과 기존 이름, 선택 불가)
5. 체크한 후보만 **[선택한 후보 등록]** → "후보" 상태로 기존 DB에 저장

### 11.3 중복 기준

- **같은 플랫폼 + 같은 계정**이면 중복입니다. 주소 형식이 달라도 같은 계정으로 봅니다.
  예: `https://www.tiktok.com/@BanhNgon.VN?lang=vi` = `@banhngon.vn`
- 다른 플랫폼의 같은 이름은 중복이 아닙니다.
- YouTube는 채널 ID 주소(`/channel/UC...`)와 핸들 주소(`/@이름`)를 같은 채널로 알아보지 못합니다. 같은 형식으로 저장해 주세요.

### 11.4 TikTok One 연계 (API 없이)

- TikTok One의 크리에이터 검색 API는 **일반 광고주 권한이 확인되지 않아 연결하지 않았습니다.** 권한이 실제로 확인될 때만 추가합니다.
- TikTok One에서 검색 결과를 **CSV로 바로 내보낼 수 있는지는 확인되지 않아**, 우리 발굴 CSV 양식에 옮겨 적는 방식을 씁니다.
- 비공식 로그인 자동화, 접근 제한 우회, 크롤링은 하지 않습니다.
- 제공 기능: [TikTok One 열기], [크리에이터 검색 공식 안내], [검색 기준 복사], 후보 직접 입력(중복 확인 포함), 발굴 CSV 가져오기.
- TikTok One 화면에서 직접 본 값은 **"직접 확인한 값"(신뢰 높음)**으로 저장합니다.

## 12. I08·I12·I14 — 외부 API 연동

### 12.1 서비스별 정리

| 서비스 | 할 수 있는 것 | 출처 종류 | 키 확보와 무료 시험 가능성 |
| --- | --- | --- | --- |
| YouTube Data API v3 | 구독자·총 조회수·영상 수, 최근 영상 15개 조회수 중앙값, 베트남 채널 검색, 일괄 갱신 | 공식 API 확인값 | **무료.** Google Cloud 콘솔에서 키 발급, 하루 10,000유닛 |
| Phyllo | 연결 확인(지원 플랫폼), 공개 프로필 분석 시도(팔로워·평균 조회수·참여율) | 전문 SaaS 제공값 | 대시보드 가입 후 sandbox 키 발급. **공개 분석은 요금제에 따라 막힐 수 있음** |
| Modash | 크리에이터 검색(국가·팔로워·조회수 중앙값·참여율·언어·시청자 국가), 남은 크레딧 | 전문 SaaS 제공값 | **유료 별도 계약** (공식 안내: Discovery API 연 $16,200부터). 시험 크레딧은 영업 상담으로 요청 |
| HypeAuditor | 크리에이터 검색(국가·팔로워·평균 조회수·참여율·언어·시청자 국가), 남은 조회 수 | 전문 SaaS 제공값 (샌드박스는 시연 데이터) | API 계약 필요. **가격·무료 시험 여부는 공개 문서에서 확인되지 않음.** 문서에 샌드박스 검색 경로(`auditor.searchSandbox`)는 있음 |
| TikTok One | API 연동 없음 | 화면에서 직접 확인한 값 | 광고주 계정으로 화면 이용 |

※ "무료"로 확정한 것은 YouTube뿐입니다. 나머지는 무료라고 단정하지 않습니다.

### 12.2 구조 (어댑터)

- `external_api.py`: 서비스별 호출·인증·오류 안내·호출 기록·서비스 상태 (YouTube·Phyllo 기존 함수 유지, Modash·HypeAuditor 추가)
- `discovery.py`: 제공업체 목록, 결과를 **표준 후보 레코드**로 변환, 조건 재적용, 중복 키, 기존 DB 형식으로 변환
- 표준 후보 레코드: 이름, 핸들, 플랫폼, 프로필 URL, 팔로워, 조회수 중앙값, 평균 조회수, 조회수 기준, 참여율(%), 베트남 시청자 비중(%), 활동 국가, 언어, 제공업체, 출처 종류, 수집일, 신뢰 수준, 확인 불가 조건, 등록 여부
- **API가 주지 않은 값은 만들지 않습니다(빈 칸).** 평균만 준 서비스(Phyllo·HypeAuditor)의 값은 중앙값 칸에 넣지 않습니다. Modash는 `calculationMethod=median`으로 요청해 중앙값으로 받습니다.
- Modash·HypeAuditor의 **응답 필드 구조는 공개 문서에 자세히 나와 있지 않아**, 이름으로 값을 찾고 못 찾으면 비워 둡니다. 실제 키로 처음 확인할 때 결과가 비어 있으면 응답 구조를 맞춰야 합니다.

### 12.3 [연결 여부 확인] 탭

서비스별로 다음을 보여 줍니다: 설정 여부, 환경(sandbox/production), 연결 확인 버튼, 연결 성공/실패, **권한 부족**, **크레딧·사용량**(YouTube는 이번 실행 기준 유닛, Modash·HypeAuditor는 응답에 있을 때), **마지막 성공 시각**, **오류 원인과 대응 방법**, 키 확보 방법, 환경변수 이름. TikTok One은 "API 미연동" 카드와 이동 버튼만 둡니다.

- **선택 연동 접힘**: Modash·HypeAuditor는 "있으면 쓰는" 유료 API라서, **키가 없으면 [연결 여부 확인] 탭과 [발굴] 탭의 '조회할 곳'에서 "선택 연동 서비스 보기" 안에 접혀** 있습니다. 눌러서 펼쳐 볼 수는 있습니다. `.env`에 키를 넣고 서버를 다시 켜면 접힘 없이 자동으로 보입니다. YouTube·Phyllo는 항상 보입니다. 아래에 최근 호출 기록 60건이 나옵니다.

### 12.4 오류 처리

| 상황 | 화면 안내 |
| --- | --- |
| 키 없음 | 서비스 "키 없음"으로 비활성. 검색 목록에서 선택 불가, 기존 기능 영향 없음 |
| 잘못된 키 | YouTube "API 키가 올바르지 않아요" / Modash 401 / HypeAuditor 403 |
| 권한 없음 | "이 계정의 요금제·권한으로는…" + 상태에 **권한 부족** 표시 |
| 크레딧·사용량 소진 | YouTube 하루 10,000유닛 초과 / Modash·HypeAuditor 402 → 상태에 **크레딧 부족** 표시 |
| 일시 무응답 | 시간 초과·연결 거부·500 → "잠시 후 다시 시도", HypeAuditor 202 → "보고서 만드는 중" |
| 결과 없음 | 빈 목록 + TikTok One·직접 입력·CSV로 이어서 진행 안내 |

### 12.5 보안

- API 키는 **서버 환경변수(`.env`)에서만** 읽습니다. 소스코드·HTML·브라우저 JavaScript·브라우저 저장소에 넣지 않습니다.
- 화면·상태·호출 기록에는 키의 앞뒤 몇 글자만 보입니다. 시험에서 비밀키가 응답·기록에 나오지 않는 것을 확인했습니다.
- 서버 접근 통제와 안전한 비밀 저장소가 없어서, **화면에서 키를 입력하는 기능은 만들지 않았습니다.** 화면에는 설정 안내와 연결 상태 확인만 있습니다.
- `.env`는 Git에 올리지 않습니다. 키가 노출됐다면 해당 서비스에서 **새로 발급하고 이전 키는 폐기**합니다.

- 신규 테이블은 `init-db` 때 함께 만들어집니다. 이미 로컬 DB가 있다면 README 9장 규칙대로 **로컬 DB를 지우고 다시 초기화**하세요.

## 19. 구현·시험 결과 (2026-10-23)

### 19.1 시험 방법

- **임시 Flask 앱**: 상준 님의 공통 기반 대신 테스트용 레이아웃을 붙여 실제로 실행했습니다.

## 20. 발표 시연 시나리오 (2026-10-28)

아래 인물·숫자는 **가상 시연 데이터**입니다. 실제 키 없이도 1~5는 그대로 시연할 수 있습니다.

1. **[요약]** [시연 데이터 넣기] → 진행 단계·다음 할 일 설명
2. **[발굴]** 조건(TikTok·베트남·Dessert·팔로워 1만~50만) → [검색 기준 복사] → [TikTok One 열기]로 실제 화면 연결 설명
3. **[발굴] 후보 직접 입력**: TikTok One에서 본 계정을 입력 → [중복 확인] → [후보로 등록] → 출처 "직접 확인한 값·신뢰 높음" 강조
4. 같은 계정을 다시 등록 → "이미 등록된 계정" 확인 (중복 방지)
5. **[제안 메일]** 베트남어 메일 → **[회신 정리]** 회신 붙여 넣기 → **[일정]** 촬영일 확정 → **[광고 단가]** 참고가 비교 → **[내보내기]** CSV·PDF
6. (키가 있을 때) **[연결 여부 확인]** 연결 확인 → [발굴]에서 YouTube·Modash 검색 → 결과의 출처·신뢰도·"확인 불가" 표시 설명
7. 편집 창 **"지표 기록"**으로 시점별 비교 설명
